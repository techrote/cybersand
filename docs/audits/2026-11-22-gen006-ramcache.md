## Implemented integration

The [canonical contract](../systems/persistent-area-residency.md) owns current semantics.
The implementation retains real unique-owned native Worlds and matching worker host
companions, with one-use Main admission and exact receipt fences. WARM bytes are a
separate tier. The value ledger reserves native growth, immutable buffers and private
preparation before admission. A real I/O Thread publishes bounded immutable snapshots;
ACKs describe durable state without overwriting later RAM mutations. Adjacency, explicit
intent and camera signals prepare actual private destinations and pay legitimate debt.

## Memory observations and limits

The local controlled native fixture, separate from Main rendering, measured one HOT
owned allocation estimate of 30,352,240 bytes (one worker) and 30,352,552 bytes (four).
Three HOT estimates total 91,056,720 / 91,057,656 bytes. The conservative growth
reservation for the one-worker fixture is 58,582,768 bytes per native owner.

Adding the third resident increased measured process RSS by 29,573,120 / 29,659,136 bytes.
Adding the second showed larger 48,771,072 / 48,857,088-byte deltas because preparation
and allocator retention were also present. Peak sampled native-fixture RSS was
266,387,456 / 266,817,536 bytes. RSS did not immediately return to its initial value
after eviction; the ledger must not be reported as a strict process-RAM bound.

An independent requested-allocation counter at all 128 chunks with temperature and
arrival arrays measured 51,464,346 bytes versus an owned estimate 51,465,112 and initial
reservation 52,515,784. It excludes malloc metadata and OS stacks. Ordinary and
ASan/UBSan probe modes differ because ASan keeps its own allocator interception.
No measured 2048 × 1024 area capacity or many-area residency claim follows.

## Negative evidence and repaired findings

- Initial hot re-entry restored the native World but left the previous Workbench sample
  epoch in its worker companion. Real Paint refused. The companion now retains the exact
  actor-free sample/epoch, and native editing/Fire/Flatten regressions pass.
- Main handoff admission initially lacked an enforced one-use ticket. Exact serial,
  generation, operation and target receipt now gate the native transfer.
- A cache `mandatory_active` bypass could admit inactive state above a tiny budget.
  Only the acknowledged active HOT owner receives the explicit active exception.
- Late HOT/COLD/Main/release retry could fall back to an older durable manifest after a
  deferred native commit. Pending transaction fences now survive through release ACK.
- Lost ACK during healthy-only recovery initially left a quarantined storage retry loop.
  Storage-only reconciliation now acknowledges the exact published rescue snapshot.
- A stale historical `candidate_durable` flag allowed ordinary exit after later actual
  native failure. Failed-owner exit now requires explicit disclosed recovery close.
- Independent prefetch probes exposed malformed pure metadata and oversized capture
  metadata before thread transfer. Typed/byte-bounded preflight repairs are included
  before freeze; original failed probes remain retained.
- Cache authoring refresh also needed aggregate metadata preflight before encoding.
  Repeated packed-buffer aliases now refuse before serialization, and inactive
  authoring growth cannot bypass retained-memory admission. The actual focused
  ledger delta passes 380 checks; no huge allocation was attempted for reproduction.
- Independent timing review found that terminal Main stalls could be omitted and
  the original WARM sequence visited only A/B. Terminal-inclusive clipped intervals
  and balanced B/C/A samples repair both defects. Actual injected 250 ms terminal
  work is now reported, while pre/post-operation delays remain excluded.
- Independent publication attacks found contradictory original process logs and
  summary receipts could pass. The verifier now reparses the original markers,
  process exits, memory phases and cold sample files. All 15 retained negative
  probes refuse; these guard probes are metadata tests, not native execution.
- Portable source review found project configuration/extension descriptors were
  not cross-bound to executed inputs. The successor records those inputs and binds
  packaged source to both runtime provenance and actual qualification. Direct
  engine process/PID, mode, original completion and invocation-wide payload fences
  are covered by the new Windows PowerShell 5 guard campaign.
- Local LSan failed in the restricted process environment. The same local instrumented
  fixture passed ASan/UBSan with leak checking disabled. Final hosted Linux LSan is
  mandatory and is not replaced by that diagnostic result.

## Required frozen-source gates and publication

The corrected graphical pilot still attributes roughly 206 ms of Main work to
prefetch cache admission. Useful active native progression is proven, but a
matched active-control responsiveness comparison and measured validation-cost
repair remain in progress. No no-regression performance PASS follows from this
pilot or from the whole-run maximum frame gap.

`gen006-ramcache-qualification.yml` is isolated to this branch and an explicit versioned
publication request. It retains donor regressions, native continuation and separate-process
restore, adds independent ownership/lifetime attacks, process death, failed-active rescue,
real graphical Main and ordinary Workbench, and requires 30 HOT/30 WARM samples at
workers 1 and 4. Every receipt is rebound to actual engine PIDs, original logs/files,
source input hashes and the built runtime. Skips and diagnostic runs cannot publish.

Native ASan/UBSan/LSan covers core continuation, World storage and render-lease lifetime.
The GDExtension registry and GDScript private-thread lifecycle have separate actual
unsanitized Linux/Windows tests; they are not represented as instrumented coverage.

The Windows evaluator includes pinned Godot, source-matched native DLL, ordinary and
persistent launchers, isolated profiles, real graphical smoke, failure capture and the
[owner guide](../operations/persistent-area-ramcache-evaluation.md). The publication
workflow may change only its four established runtime/provenance paths. Final run IDs,
runtime hashes, ZIP checksum, controlled distributions and final PR HEAD will be added
after that campaign. At this checkpoint none of those pending final gates is a PASS.

## Remaining product boundary and next admission

General moving-chunk streaming, non-square native extent qualification, arbitrary
actor/Rapier/controller persistence, unsupported solvers, cross-area material flux and
recipe reconciliation remain future work. Profiles are runtime-bound; no automatic
migration from the donor DLL/SO is promised. Physical Windows 11/NVIDIA playfeel and
performance remain an owner acceptance step.

After qualification, the next narrow admission should be owner evaluation of HOT travel,
memory pressure, deferred Save/restart and camera/intent prediction on the actual Windows
machine. Any subsequent actor traveller or larger connected-area milestone should be
based on these measured limits and an explicit new continuation domain.
