## Native mechanism and refusal guarantees

One immutable per-World profile contains fixed numeric tables. An absent or
effectively default profile retains the original fast path. Material-profile
lookups in pool workers allocate nothing, parse no strings and acquire no profile
lock. The
existing owner mutex and completed-tick boundary serialize activation. The host
mailbox is lazy, accepts one pending request and retains sixteen copied receipts.

A request binds host session, native World identity, expected prior revision and
a complete replacement profile. Omitted values inherit accepted defaults. Native
code independently checks identity/revision, schema, bounds, applicability,
allocation and capacity before swapping. Old, stopped, cancelled, failed and
retired requests cannot silently configure a replacement World. An absent or
expired receipt does not invent a refusal; postcommit readback trouble does not
pretend the native activation failed. New UI edits remain distinct from an older
acknowledgement.

Changed configurations scan resident nonempty chunks once, capped at 16 Mi cells,
and wake existing affected blocks and immediate boundary neighbours. Equivalent
and repeated equivalent profiles scan and wake zero cells/blocks. This is a
bounded user-triggered transition cost, with no scheduler redesign.
