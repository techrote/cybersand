## Independent review of A's CPU and memory observer

`strata_process_metrics.py` observes the launched process and discovered descendants at a bounded 0.5-second cadence. This distinction matters on Windows, where the console executable owns a separate engine process. Linux uses `/proc` with namespace consistency, process start identity, CPU tick conversion and RSS page conversion. Windows uses typed Toolhelp32 inventory, query-only OpenProcess handles, GetProcessTimes and GetProcessMemoryInfo; snapshot and process handles are closed in `finally` blocks. The ctypes PROCESSENTRY32W and PROCESS_MEMORY_COUNTERS layouts use pointer-sized fields, and FILETIME counters are combined as unsigned 64-bit values before conversion.

The observer fences PID reuse with creation identity, retains known descendants, limits process inventory, observed identities, samples and diagnostic errors, and kills an unbounded target on timeout or exceptional cleanup. It records raw samples and separate original process/log/resource receipts. C's verifier independently recomputes process identities, cumulative observed CPU and peak simultaneous RSS from raw sample rows, and requires the actual GDScript engine PID to occur in those rows for scene and maximum-extent measurements.

The real Python child-process tests cover CPU/allocation, a child descendant, retained timeout and zero-exit SCRIPT ERROR refusal. They passed on Linux. The Windows API path also ran in campaign 2: each actual engine child PID appears in the retained raw sample rows, independently of its console wrapper. Recomputed CPU and peak working-set aggregates match all six original Windows phase receipts; no observation errors were recorded.

These observations are deliberately limited: CPU is the sum of last observed process user/kernel counters; sampled RSS/working-set peaks can miss short-lived descendants and exit tails, and shared pages can be counted more than once. OS peak counters remain separate. There is no GPU memory or physical presented-FPS measurement. The per-mode Godot samples report callback intervals and tracked memory with composition resources retained even in disabled mode. The pre-Strata bootstrap sample is identified separately and is not a matched-scene performance baseline.
