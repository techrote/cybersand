# Grey Area 51 implementation checkpoint

## Request and source boundary

The owner requested Grey Area 51 as **five tiles across and one high, mostly
solid concrete**, continuing the earlier emphasis on detailed scene aesthetics
and deliberate connections. This scene uses a single native concrete slab with
narrow transfer corridors, inspection slits, sealed machinery and cast shielding.
The route alternates between upper security passages and low service tunnels.

Work began from current main **`02f9c890dc4faf0bf132a95acbc13a4d9cdc002f`**, after
Blacksite Nine had merged. The isolated branch is **`scene/grey-area-51`** in
`techrote/cybersand`. The local implementation checkpoint is
**`d9b19dbf4895588fe19abee6520d3864ce307829`**, tree
**`0ea8a5dfbd914b8026c4a53ff05469e92cb86275`**. Captures use that committed

## Presentation and controls

The combined launcher includes Grey Area 51. **Ctrl+F11** and
**`--grey-area-51`** provide direct desktop entry; the Web demo list includes
the same complete definition. The scene starts paused. **A/D** move the default
sampled character, held **Space** supplies upward thrust, **P** animates,
**F** follows, arrows pan, **F8** toggles the clean view and **R** restores the
entire bunker. The follow camera is 320 × 192 and stays within the single
vertical strip.

One shared presenter owns Blacksite/Grey navigation, the world minimum-size
lease and modal release fences. Grey exposes five tile buttons plus an overview;
Blacksite retains nine. Direct switches restore the correct labels, dimensions
and shaders. Tile selection performs no native reconstruction, player movement
or simulation-policy change. The fixed native interest covers the whole strip.

Desktop F5 uses the existing exploratory actor admission and reset protocol.
The shared keyboard gate now includes vertical movement, trim, reel, ability
and equipment keys as well as horizontal movement. Both logical and physical
key state must be released after a map closes. The actor badge uses the actual
published actor centre.

The Grey-only Concrete finish adds restrained aggregate, formwork joints, tie
holes, damp streaks and edge exposure. The scene grade reads immutable material
and rendered-colour textures. Its layer is above material/glow rendering and
below actor, usable and brush foreground graphics. Static Concrete erasure
appears immediately; only the ordinary moving-material transition set consults
a fading previous cell. Both scene effects use absolute world coordinates.

## Runtime, captures and limits

Validation used **Godot 4.7.stable.official.5b4e0cb0f**, the current retained
Linux native extension (SHA-256
`5bdc55e7f355004fc8a6468234b0d018d3919339ebfe47faca9997de3af17847`) and
Rapier 0.35.2. All **37 native provenance inputs** and **18 retained LFS
runtime files** match their pins. Rendering used X11 and software OpenGL 4.5
through Mesa 25.2.8 / llvmpipe. The isolated display requires local IPC access.

The retained [overview](../images/grey-area-51/grey-area-51.png) is
**3840 × 768**, four pixels per native cell. All five **768 × 768** tile PNGs
are crops of that same paused, tick-zero framebuffer. Their concatenation must
reproduce the atlas decoded pixel data byte-for-byte. The [capture manifest](../images/grey-area-51/capture.json)
records the actual accepted definition and runtime. Its revision field is
`unavailable` / `not-embedded`; the evidence manifest separately binds the
capture apparatus and complete Grey implementation bytes to the local
implementation checkpoint. The
[portable definition](../images/grey-area-51/grey-area-51.scenario.json) includes
one final newline beyond the canonical byte count.

This is Linux/native and software-rendered evidence. The synchronous Web
controller ran on Linux, not in a browser or WASM build. It does not qualify
every physical actor for the 24-cell passages, replace physics-programme gates,
or claim Windows, browser, full CI or merge acceptance. Repository, documentation
and retrieval checks are recorded separately in the evidence manifest.
