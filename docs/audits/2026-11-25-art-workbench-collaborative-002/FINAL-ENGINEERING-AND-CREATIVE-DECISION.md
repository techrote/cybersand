## The owner experience

Art remains one ordinary Workbench window with a shared conversation and provider.
The collaborative pages are Conversation, Creative brief, Proposal and Context.
The existing direct-authoring page stays available for convenient bounded work.

| Owner action | Working behavior | Native authority |
| --- | --- | --- |
| Discuss | Inspect admitted context, ask questions, compare ideas and retain the complete redacted answer. | No native drawing. |
| Direct authoring | Send a bounded material-paint request through the established route. | Existing executor and source-material restrictions; positive turn count or duration required. |
| Propose | Receive a versioned proposal with intended stages, materials, scope, assumptions and unresolved questions. | Compile and preview only. |
| Develop | Send a refinement with the current normalized proposal, applied brief and recent admitted discussion. | New lineage/differences; no inherited execution approval. |
| Approve next stage | Inspect host-computed effects, then approve one applicable finite stage. | Fresh source, policy, dependencies and material-plane checks before native execution. |
| Review | Discuss current observations and acknowledged native work. | A suggested improvement still needs a fresh proposal/approval cycle. |

The Creative brief has explicit Apply/Cancel. It records objectives, style,
complexity, variation, palette, target region, protected rectangles and destructive
permission. Unapplied changes block Send, avoiding ambiguity about which brief
the model will receive. Focus controls use the current view, a bounded centered
region or the ordinary PAINT selection. Manual drawing remains available.

The Context inspector explains available information, selected information,
provenance and omissions. External transmission requires applicable owner
authorization of the inspected context. A changed context invalidates that
authorization. Optional images are bounded Workbench canvas captures, with
native coordinate mapping and hashes; they do not silently capture the desktop,
unrelated windows, private files or historical audit content.

The Proposal page shows stages and dependencies, host-computed cell scope,
materials, warnings and unsupported or unresolved instructions. Refresh preview
writes nothing. Approve next stage is fresh approval for one stage. Revise selects
Develop without sending. **Skip retires the remaining preview and requires a
new plan; it does not silently execute later dependent stages.** Copy preserves
the complete structured proposal. Historical revisions stay reviewable without
retaining approval.

Conversation search operates over complete admitted text in small slices and
states its newest-128-match display bound. Full messages remain accessible in
4,096-character parts. Large Conversation Apply prepares copied values in the
existing finite worker mechanism; its draft stays readable and Cancel remains
available. A durable complete audit append precedes live adoption, and adoption
precedes synchronous traffic observers. Cancel, Stop, Conversation-editor hide or
close, owner retirement, new turns,
World replacement and credential changes fence stale preparation. Conversation
editing never creates a native Undo entry.

The accepted #727 session-only behavior remains: Hide preserves the current
session; a new game session starts a new conversation. Complete redacted audit
records are retained, but historical conversation, World references and execution
approvals are not automatically restored. There is no automatic cross-session
creative-brief import or indefinite autonomous authoring loop.

## Native context and constraints

Art observes real native stored material through the existing PAINT capture
owner. It does not drain the native mailbox independently or construct a second
World. Native captures supply copied material values with generation, revision,
tick and authoring-generation identity. A private full bounded plane supports
validation; it is not automatically transmitted to the model.

The disclosed model context includes World dimensions, selected region,
observed material names/counts, a 16×16 coarse occupancy/eligibility grid, at most
32 spatially distributed observed cells, tool state, applied creative constraints,
bounded recent decisions and construction limits. It explicitly distinguishes
stored material from rendered appearance, body coverage, actor intent and
physical traversability. No unsampled cell identity or hidden structure is
invented.

| Boundary | Host-enforced limit |
| --- | --- |
| Native region capture | 262,144 cells |
| Model native/creative context | 24,576 UTF-8 bytes |
| Recent conversation selection | Eight messages, at most 4,096 characters each and 16,384 characters in total |
| Approved reference cards | At most three selected from four frozen cards; 4,096-byte card budget |
| Proposal packet | 131,072 bytes |
| Proposal construction | Eight stages; 64 expanded native operations |
| Conservative candidate scope | 262,144 cells per stage; 1,048,576 across the proposal |
| Native execution chunk | At most 4,096 cells |
| Response body | Existing 16 MiB finite transport bound |

The knowledge selector uses deterministic brief/style relevance and exposes
matched terms, provenance and omitted cards. Its accepted native-authority
reference is source `00cdb02f103265b6dc5224c68283e9a0c8cb449f`; GOLDMAPS interpretation
and rubric cards are pinned to
`b9535405853a5cd16e4bba968ec7167222861c42` in `techrote/sandmapsreference`.
It does not import unfinished Docs branches, search private files, ingest old
audit history or treat retrieved examples as executable instructions. It is a
small bounded reference system, not a general semantic retrieval engine.

Explicit region, palette, protected rectangles, source and destructive rules are
validated by the compiler/executor. Natural-language style, density and creative
intent guide the model but are not all mechanically enforceable. A protected
passage should be expressed geometrically when it must be a hard exclusion.
Native body exclusions remain authoritative at execution.

## Construction and revision authority

The compiler supports rectangles, outlines, discs, lines, pixels, polylines,
polygons, seeded bounded airbrush detail and single-level repetition. It computes
finite geometry and resource scope itself. Unknown operations, forged host
budgets/receipts, contradictory constraints and unresolved execution questions
refuse. Native parts remain with their Architecture owner; descriptive references
do not install or execute them.

Preview applies the established rasterization rules to copied native values and
shows predicted material differences without writes. Approval checks the live
source, applied policy, dependencies and complete selected-plane hash. Execution
uses the existing Art executor and exclusive simulation worker; admission and
actual consumption both check source identity. Only a completed native receipt
advances the expected source for the next chunk.

The native source policy remains **Empty (0) and Hard Wall (58)**. Destructive
permission can authorize supported removal/replacement within that authority;
it does not authorize replacing occupied Metal, Stone or other protected stored
materials. A material substitution in an unexecuted proposal works. Replacing
already installed protected material requires its ordinary owning editor.

Develop retains proposal lineage and differences while keeping the applied owner
brief as a host input. Stale work cannot silently execute after manual editing.
The source fence is deliberately conservative: a source change can retire a
proposal even where a more elaborate dependency-local analysis might retain it.

Stop keeps the actual acknowledged prefix. Completion followed by cancelled or
failed verification retains a truthful completed-but-unverified receipt instead
of losing it or inventing success. Continuation needs fresh observation and
approval. Undo/Redo remains the existing native history authority. A series of
separately approved native operations is never described as one atomic
multi-stage transaction.
