## Exact transport contract

The owner installs `ArtProposalTransport.bind_owner(existing_art_panel.provider, art_configuration_snapshot, owner_guard)`, then injects `dispatch(request, completion_callback, pre_dispatch_guard) -> {ok, provider_id, ...}` and `cancel(provider_id, request_id, reason)`. Completion is `(id: int, text: String, response: Dictionary, error: String)`; the small response is a host-owned lifecycle record, not the raw provider envelope or an execution receipt. Each request has one captured identity/consumer. Request fields cannot override Art's endpoint, model, credential, image or context configuration. The source-pinned [contract](https://github.com/techrote/cybersand/blob/bcc92927ce3894a16d5544923cfbf7b1d0339fda/docs/systems/art-owned-proposal-transport.md) names the eleven-argument Provider guard and the bounded modes/capacities.

Transport errors, absent listener/connection refusal, timeout/no headers, non-success HTTP, malformed provider JSON, explicit provider error envelopes, OpenAI Responses refusal/incomplete output, Chat Completions token-limit termination and empty text cannot enter native authoring for that response. Oversized bodies are bounded at16MiB; only the admitted redacted content is retained, not an unbounded remote stream. Malformed typed proposals remain in Conversation and refuse compilation. Full admitted redacted envelopes remain in Traffic; short UI errors are not the complete audit.

Do not promise comprehensive semantics for every custom model's proprietary refusal/status fields. Host compilation and fresh native approval remain the executable boundary. Strict JSON-schema generation is not enabled or proven merely because a model can return structured text.

## Owner-operated real-model protocol

Use an already installed owner-selected local model; enable its API server explicitly and enter its exact served identifier and numeric `http://127.0.0.1:1234/v1` base address when that is the actual configured endpoint. Image input starts off. `localhost` is intentionally classified as an unverified hostname, and non-numeric-loopback endpoints need exact-context transmission authorization. Presets are editable convenience values, not discovery, access or free-inference promises.

Inspect a small paused native region, check the disclosure, then send one Discuss request and verify zero writes. Propose one bounded improvement with a protected passage, inspect the host preview and approve one stage. Develop a revision, deliberately edit a relevant native region before approval and confirm stale refusal; reinspect/replan explicitly. Review actual acknowledged results. Optional images require inspecting the selected canvas crop and the applicable disclosure authorization. Do not transmit unrelated files or historical audit content.

For the24-brief cohort, freeze initial saved geometry/region/palette/protection, model identity and parameters; compare complete workflows from matched starts, retain refusals and partial results, and use genuinely unseen future held-out texts. Record actual requests, returned usage, observed latency, approvals, native receipts and individual owner ratings. Retrieval ablations vary only admitted knowledge/native context; identical fixture proposals cannot demonstrate a model-decision improvement. Missing usage/cost stays unknown.

Opening the launcher/Art panels, binding a transport, choosing a preset, inspecting context or selecting an offline example does not send a model request. The evaluator startup source creates the ordinary panel and observes it without a send call; final actual startup and explicit-loopback cases support that fact. Only explicit Send admits a provider request. An offline example previews host-authored deterministic data and does not construct its baseline scene silently.
