## Exact transport contract

The owner installs `ArtProposalTransport.bind_owner(existing_art_panel.provider, art_configuration_snapshot, owner_guard)`, then injects `dispatch(request, completion_callback, pre_dispatch_guard) -> {ok, provider_id, ...}` and `cancel(provider_id, request_id, reason)`. Completion is `(id: int, text: String, response: Dictionary, error: String)`; the small response is a host-owned lifecycle record, not the raw provider envelope or an execution receipt. Each request has one captured identity/consumer. Request fields cannot override Art's endpoint, model, credential, image or context configuration. The source-pinned [contract](https://github.com/techrote/cybersand/blob/d503d824aac4128968f7dfba5dccd540c3c07b59/docs/systems/art-owned-proposal-transport.md) names the eleven-argument Provider guard and the bounded modes/capacities.

Transport errors, absent listener/connection refusal, timeout/no headers, non-success HTTP, malformed provider JSON, explicit provider error envelopes, OpenAI Responses refusal/incomplete output, Chat Completions token-limit termination and empty text cannot enter native authoring for that response. Oversized bodies are bounded at 16 MiB; only the admitted redacted content is retained, not an unbounded remote stream. Malformed typed proposals remain in Conversation and refuse compilation. Full admitted redacted envelopes remain in Traffic; short UI errors are not the complete audit.

Do not promise comprehensive semantics for every custom model's proprietary refusal/status fields. Host compilation and fresh native approval remain the executable boundary. Strict JSON-schema generation is not enabled or proven merely because a model can return structured text.
