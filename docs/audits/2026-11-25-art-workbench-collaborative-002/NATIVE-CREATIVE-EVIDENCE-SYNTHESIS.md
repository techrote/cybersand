# Native construction and creative evidence

**The source-bound evidence establishes real editable native construction,
bounded proposal control and reproducible recovery mechanisms. It does not
establish genuine model creativity or physical actor traversal.**

This synthesis concerns the complete displayed Linux campaign at
`2743f89a0df6f6afcf7484e859c10790d521e74b`, tree
`56687bcaa8eb58fbdf1bbeb673d74a40dcc9b634`. Later Context improvements and
Conversation Apply changes have separate source identities and qualifications.
A future combined source or Windows package does not inherit this pass merely
by including the same example names.

There is **one actual scripted Develop exchange** in that session campaign,
plus additional owner-style proposal replacement/replanning controls. This is
not evidence of an extended genuine-model design conversation. The fixture
transport establishes routing and lifecycle behavior; no model authored those
responses.

## What the comparisons establish

For all 17 ready copied-value briefs, the same frozen proposal produces identical
geometry when flattened into one stage, when knowledge is disabled and when
the model-visible native summary is disabled. The host still retains its private
native values for validation and preview. The observed context-size ranges are:

| Admitted model context | UTF-8 bytes in the 17 ready brief controls |
| --- | ---: |
| Native summary and selected knowledge | 7,006–8,374 |
| Knowledge disabled | 6,109–6,224 |
| Native summary disabled | 3,317–4,689 |

Those controls establish deterministic compiler behavior, opt-out behavior and
payload costs. They cannot establish that retrieval or native context improves
a model's decisions, because no model chooses a different proposal.

The actual-native direct/staged controls establish executor compatibility and
equal final geometry. Summed equally scoped native executor intervals were
9.100183 s for staged submissions and 7.657192 s for direct controls. Their fixed
arm order and different chunk/stage boundaries prevent a general speed claim.
The broader 25.711573 s staged interval includes verification and artifact work;
it is not comparable with the direct executor-only interval.

The separately qualified [Context scan investigation](CONTEXT-SCAN-PERFORMANCE.md)
does provide a controlled computation comparison: one process, alternating
baseline/candidate order, authentic recorded planes and identical model/context
digests. It remains a Context.build result, not an artistic or native execution
comparison.

## Decision and owner acceptance limits

The evidence supports shipping these fixtures and controls in a Draft/HOLD
evaluator as editable native examples, compiler/context exercises and an
owner-operated conversational workflow. It supports strong claims about bounded
source/palette/protection enforcement and actual completion receipts.

It does not yet support claims of genuine LLM creativity, semantic success on
all 24 briefs, actor traversal, structural load-bearing behavior, functional
machinery, a causal retrieval benefit or a qualified combined Architecture
module-placement executor. Ordinary Art's restriction to source materials 0 and 58 also means
that later repainting of an already introduced accent made from any other material needs another
applicable native authority; destructive permission alone does not expand it.

The [owner-operated genuine-model protocol and qualitative rubric](NATIVE-INDEPENDENT-REVIEW.md)
provide the next acceptance layer: freeze matched starting native Worlds and
policies, retain all refused/incomplete outcomes, counterbalance context arms,
record the served model/runtime and complete redacted responses, approve actual
stages and rate visible geometry and usefulness separately from safety gates.
Until those authorized runs occur, genuine model calls remain **zero**.

The earlier eight-of-nine exit 137 attempt and temporary evidence loss remain
separate retained negatives. The source-pinned successful campaign does not
erase them. The original physical Windows/NVIDIA absent-listener acceptance
remains owner-pending, and this synthesis does not qualify a later portable ZIP.
