## Delivered authoring capabilities

### Native modules

The module library harvests exact local-coordinate little-endian material
planes from completed native Batch tiles or a supported inspected World
region. It stores bounds, anchor, explicit transformation permissions, material
identities, declared roles, optional connectors, clearances, protected regions,
fixed/variable geometry, recipe and provenance. Geometry observation is
separate from authored or inferred semantic intent. Imported metadata cannot
assert current native observation.

The Workbench supports harvest, inspect, name/tag, search/filter, import/export,
save/reopen, placement, finite repetition, palette substitution and bounded
seeded detail variation. Placement and replay use the existing native executor
and ordinary Undo/Redo history. Empty module cells are transparent; separately
declared empty clearances are checked against the actual World.

Eight starter parts are constructed in private native Batch Worlds and then
harvested: buttressed column, Warren beam, ribbed floor, service doorway, return
pipe, suspended gallery, machine housing and stepped transition. The module
format defines thirteen vocabulary categories, including an explicit
unclassified category for geometry without asserted architectural meaning.

Supported transformations are identity, horizontal/vertical mirror and exact
90/180/270-degree rotations, subject to each part's declared permissions.
Required point/socket/receptor connections must match supported compatibility,
facing and actual occupied geometry. Optional attachment lines remain preserved
metadata; required attachment-line matching is explicitly refused. Point
matching does not promise one-to-one socket occupancy or load capacity.
Palette compatibility is an authored permission, not physical equivalence.
Seeded thinning can fragment variable detail and is not used to weaken the
primary geometry in the representative module compositions.

### Retrieval

Twenty-five compact, source-bound GOLDMAPS design cards describe topology,
scale, hierarchy, negative space, support, repetition, asymmetry, connections,
materials, motifs, failure modes and applicable construction strategies.
Observed source facts and architectural interpretations are separately labelled.
No private artwork collection or reference-repository duplicate is shipped.

The offline deterministic ranker supports structural intent, family, scale,
topology, connections, negative space, palette/character and native-module
compatibility. It returns a bounded context pack: normally three references,
at most five, within 12,000 characters. No-fit and context-budget omissions are
explicit. Qualified native module candidates and historical metadata-only
candidates are distinguished; selection never bypasses host placement checks.

### Staged construction

The implemented interaction is:

**Intent / typed plan → inspect actual World → retrieve references → compile
zero-write preview → Approve, Revise or Skip → native application → inspect
receipts/readback → continue.**

Plans declare intent, required region, dependencies, selected modules,
transformations, material roles, protected boundaries, clearances/connections,
budget, expected effects, uncertainty and refusal conditions. The host computes
actual footprints, source permissions and resource use. Model estimates or
serialized completion flags carry no execution authority.

A preview is a static compilation projection with zero writes, not speculative
simulation. Approval re-inspects the actual source and completed dependencies,
then validates hashes, generation, plan and module identities before queuing
native work. The final selected-region recapture follows any awaited dependency
inspection, closing the concurrent ordinary-edit race found during cross-review.
Only acknowledged native execution with exact final readback can be completed.
A no-op stage can complete after fresh exact inspection with zero new writes;
that observation is not newly constructed geometry. Nonzero stages require all
checked cells confirmed, no exclusions/refusals, matching changed counts and an
exact final material plane.

Revision clears approval. Skip does not satisfy a dependency. Stop/cancellation
retains any acknowledged prefix and actual outcome. Recovery starts from fresh
inspection. Session reopening is historical review, never automatic queue
resumption; authored World saving uses ordinary Workbench persistence.

Current host limits are 32 stages, 64 module instances and 2,048 drawing
operations per stage, a 512 × 512 maximum stage region, 262,144 changed native
cells and 1,048,576 raster candidates. Module documents are bounded to 2 MiB,
the module library to 128 entries/64 MiB, and the complete session envelope
(including imported history) to 64 MiB. The active session permits at most 256
new records; imported historical records remain under the total byte bound.
Changing an occupied source cell remains restricted to the
accepted Empty/Hardwall source domain; importing a palette does not expand
native write permission.

## Architectural experiments and negative findings

The frozen comparison registers three families, five offline arms and two
seeds: thirty attempts. Families are industrial hangar, service network and
organic cavern; seeds are 37901 and 37917. Arms are hand-authored typed plans,
deterministic procedural modules, random-valid controls, reference-guided
construction and retrieval-guided module selection. The corpus, registration,
budgets, seeds and example identities are frozen.

The development comparison completed all thirty native attempts. Each matched
family/seed block has the same initial plane/context and 144 newly painted
detail cells per arm. Hand, procedural, reference and retrieval arms deliberately
produce byte-identical geometry within each block. They pass contextual checks
in 24/24 cases; random-valid placements pass in 0/6. This demonstrates an
executable comparison and useful context diagnostics, not retrieval causality
or architectural superiority.

All thirty development cases preserve protection and the tested five-cell square
geometric route. Random cases nevertheless miss intended anchor/zone context
and sometimes intrude into declared passages. Route existence, painted-cell
count and broad connectivity alone are therefore inadequate detail-quality
criteria. The independent reducer retains failed/partial/stopped/unevaluable
cases in the denominator rather than silently discarding them.

The actual retrieval rankings for the three tasks are 146/153/159,
136/159/168 and 125/130/207. Service reference 159 is second in its retrieved
pack, not first. The available native pool contains three deliberately typed
comparison parts; these fixtures qualify the retrieval-to-module-to-native path,
not broad module-search performance. Actual model calls are zero.

Final-source Linux, Windows source and freshly extracted Windows runs each
reproduced all thirty completed, evaluable attempts with the same findings:
24/24 context-aware passes, 0/6 random-valid context passes, 144 new cells per
case, unchanged protection and the tested geometric route preserved. All four
context-aware arms remain byte-identical within the six family/seed blocks.
These are platform replications of the same thirty registered attempts, not
ninety independent experimental trials. Specialist C's independent operation
replay reconstructed the native readback hashes without importing the
production compiler or metric reducer.

A separate [exploratory negative-space review](exploratory-negative-space-review.md)
checked a five-cell-square empty probe at 25 explicitly declared stage-level
clearance centers.
All probes fit, but some buildings' center points occupy separate empty-space
components. The probe permits unrestricted four-neighbor motion and has no
actor, gravity or spawn semantics. It requires no mutual connection between
centers and applies no penalty to sealed equipment cavities. This post-hoc
diagnostic was independently cross-checked; it is not part of the frozen
comparison, a new acceptance gate, or evidence that every room is playable.

Architectural review also retained two distinct corrective histories. Five of
the original six typed examples had detached larger service assemblies despite
locally attached detail. Explicit supports repaired those gaps. The first
modular examples had corner-only truss braces, detached housing ribs and
fragmented thinned detail; revised exact geometry and unthinned primary parts
repaired those defects. Original planes, receipts, diagnostics and source
checkpoints remain in the development archive/bundle. A single connected
material component is a useful geometric diagnostic, not proof of strength,
stability or visual quality.

Three interrupted local runs exited 137 during shared-host memory/disk pressure
without a preceding native/assertion error. They remain interrupted outcomes,
not passes; the timing does not prove their exact kernel-level cause. The
earlier complete 44-process development campaign and later
22-check UI/170-check modular witnesses retain their own source identities.
Only the final exact-source hosted artifacts qualify the delivered application.
