## Source-supported lifetime repair and remaining proof

At exact upstream `5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88`:

- [TextServerAdvanced](https://github.com/godotengine/godot/blob/5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88/modules/text_server_adv/text_server_adv.cpp)
  and [TextServerFallback](https://github.com/godotengine/godot/blob/5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88/modules/text_server_fb/text_server_fb.cpp)
  normally publish the retained mutable glyph atlas directly; the mipmap branch
  creates a private Image first. Subsequent glyph rasterization calls `ptrw()`
  on the retained atlas. Font mutexes do not cover the renderer's later work.
- [RenderingServerDefault](https://github.com/godotengine/godot/blob/5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88/servers/rendering/rendering_server_default.h)
  queues those Image references for the Separate owner. A retained reference
  protects lifetime but does not freeze the referenced object's bytes.
- [CowData](https://github.com/godotengine/godot/blob/5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88/core/templates/cowdata.h)
  temporarily sets its pointer to null during `_copy_to_new_buffer_exact`.
  The concurrent renderer can read that transient empty array.
- [GLES texture storage](https://github.com/godotengine/godot/blob/5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88/drivers/gles3/storage/texture_storage.cpp)
  copies `img->get_data()` and later accesses `read[ofs]` for the upload. It
  checks dimensions, not concurrent Image ownership. This explains the observed
  byte-zero failure without attributing it to a graphics driver.

This source chain and the controlled Linux result justify a bounded ownership
repair. They do not provide a symbolized Windows crash stack; successful repaired
font and ordinary Workbench execution remain required. Main's Full two-slot
publisher already duplicates its upload Images in frozen c90 and the executed
successor, so duplicating every material plane again is not a justified fix.

The separate [engine experiment](../../../tools/pubpres_final_engine/README.md)
adds a private Image at the ten font publication boundaries after existing
alpha-edge/mipmap work. It preserves the original engine and all required
pixel/history gates. New engine build, public API equivalence, unchanged font
framebuffer controls, ordinary Workbench and same-engine Safe/Separate gameplay
must all execute before any renderer qualification or performance decision.
