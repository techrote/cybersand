# Independent endpoint and causal-reader peer reviews

## Submerged endpoint mechanism

The separate headless reproduction is independently corroborated. The peer
reader checks the actual official engine, native and Rapier bytes, exact
application source `498fa47d`, unchanged native inputs relative to build source
`c2f8a73d`, and the declared read-only observer overlay. All eight actual body
RIDs are unique and stable through seven captures. It independently decodes
112 RG8 crop planes, checks their hashes, reconstructs cell-center occupancy and
proves that the crop bounds contain every reconstructed footprint cell.

At the settled paused terminal, the native frame, GCR response and actual
physical body owners join World 3, session/epoch 1, native tick 600, sample 601
and generation 1. Each of slots 4/5/6 contains 21 Water cell centers in both
current and previous copied material images. Each native response has 21
unresolved overlaps and zero displaced cells. Both actual numeric endpoint
queries equal the direct Rapier RID pose and refuse material; the initial sweep
reason remains `bounded_pose_delta`, with zero terminal budget vetoes.

The [peer receipt](peer-reviews/submerged-endpoint-independent-peer.json)
has SHA-256 `629d9b375715aed8900ca51dce653cc727356666b8dc02c1ae4c17d8ee2af905`.
The [executed independent reader](peer-reviews/audit_endpoint_reproduction.py)
is retained without changing its bytes. No gameplay timing, original mixed-tape
equivalence, GPU visibility or physical NVIDIA claim is made.

Two measurement boundaries remain explicit. Full parent images were hashed but
not exported; the crop-to-parent origin is established by the source-bound
actual `Image.get_region` observation, not by independent slicing of complete
parent bytes. Active snapshots legitimately lag physical steps, so the strict
contemporaneous native/material/endpoint finding uses the paused terminal.
Rounded native Transform2D strings are not substituted for the exact numeric
endpoint queries.

The independent double-precision reconstruction also exposes 12 differences in
unused crop-border pixels for the barrel's approximately 3.6e-10 rad rotation:
Godot's float32 extent rounds an almost-integral edge differently. Every body
cell center still agrees, and no sampled footprint is truncated. This is not
permission to relax pixel coverage for a future shader. In particular, the
Needle's bottom at about y=496.0177 can overlap a fractional part of the adjacent
wall cell even though its 21 native cell centers are Water. A graphical
composition oracle must separately cover fractional borders and both texture
histories.

The reusable original endpoint reader was asked to enforce the same unique RID
and terminal World/session/epoch/sample/generation joins explicitly. The retained
actual data already passes those stronger peer checks. This is a validator
hardening request, not evidence that a different owner was observed.

## Prospective causal entry method

The new Windows512 causal OFF/ON/ON/OFF runner retains the existing real-step
and causal reducers. Its new interval entry was independently executed against
two unchanged prior captures: c90 Windows current-Wave2048 causal ON and c2
Linux Wave512 causal OFF. Both admit 144 genuine completions and 143 consecutive
interval rows. The runner's scope remains diagnostic perturbation measurement,
not optimization selection. The original disabled-only historical interval
reader is unchanged.

Initial peer review passed the actual data and ten integrity adversaries.
The lead then added exact scalar types and actual causal-sidecar identity,
selector, window and complete-base-observer checks. The independent review was
repeated against the same raw evidence with **22 adversaries**, including a
forged opposite supplied enablement, changed actual sidecar source/window/hash,
an incomplete observer, and a duplicate native completion with self-consistent
changed file hashes. All were refused.

has SHA-256 `8e21780974ce604ba6cfe92422e62c141a26e8cadc21578782d0a219b6e5ec7a`.

`603ee837252c343a1d70f7e9cab870eace545553d0670feb2a299f9ef296172d`.
Each report hashes the exact reviewed new source files, so later source changes
