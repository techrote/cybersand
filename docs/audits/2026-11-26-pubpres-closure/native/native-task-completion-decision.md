# Native actual-task completion: final closure decision

**Disposition: correctness qualified; comparative benefit not established; candidate not selected; all-worker completion retained.**

The complete registered 0/1/1/0 stock-Safe comparison executed all eight arms. Both small-world candidate trials were slower than both controls. The large-world improvement was inconsistent, and material freshness worsened. The original primary throughput requirement fails without relying on any newly chosen threshold. Keep `cybersand/pubpres_task_completion_barrier` false in selected and fallback product paths.

This is a definitive disposition of the native mechanism tested here. It does not choose the rendering architecture or establish complete resulting-source Workbench playability.

## Causal interpretation and rejected apparatus attempts

The small-world controls spent a median 2.367–2.471 ms in native ticks but 41.219–42.132 ms between completed physical steps. Their median upload calls were only 0.389–0.406 ms. This supports the ongoing investigation of Main/render scheduling rather than treating upload call duration as the playability outcome. Large-world controls spent a median 94.946–104.207 ms in native ticks, versus 123.527–128.527 ms physical intervals, with median upload calls 2.500–2.828 ms. Native work is materially relevant at that scale. These elapsed intervals include scheduling/preemption and overlap; they must not be summed as disjoint CPU phases. The actual-task experiment does not establish idle-worker acknowledgements as the remaining bottleneck.

The first b695 campaign was correctly refused because this kernel lacks `/proc/PID/task/PID/children`. The game captures completed, but the frozen enumerator could not discover their actual PIDs beneath the owned wrapper; CPU attribution was unavailable. Five original actual captures and three deliberate pre-application cancellations are retained. The repair adds an explicitly source-bound PPid/status fallback only for missing children files, then rereads all ancestry, creation times and the exact executable. Permission refusal never authorizes a broader search. Both independent review and a real pinned-Godot/Xorg execution verified the repaired ownership path.

The first resulting-source55 attempt exhausted the workspace while staging Rapier. It launched zero timed arms. After exact raw-archive verification, only reproducible staged project/cache copies were removed; original evidence, runtimes and sources were retained. The successful retry used the same source, native binary, engine, fixtures, order and criteria on a freshly quiet host. No timing observation spans that cleanup.

Two other prepared driver defects were repaired before comparative use: same-source task arms previously all had the candidate treatment role, and the original Wave512 identifier had a spelling mismatch. Their source and treatment identities now remain separate, with the original registration bytes preserved by an identifier-only amendment. The native candidate’s additive mixed-observer selector/readback is now included in the strict explicit derivation; the frozen callback and oracle bytes remain intact.
