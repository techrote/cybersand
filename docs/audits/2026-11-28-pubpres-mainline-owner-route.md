# PUBPRES Windows owner playtest

Use the evaluator ZIP identified in the delivery report. Extract the Actions
download, then extract the Windows ZIP inside it. Keep the extracted directory
together and run **Verify Evaluator.cmd** once. The engine and dependencies are
included.

The ordinary launchers already enable the bounded owner recorder for native,
physical, draw, presentation and spawn evidence. **F10** is the separate existing
material-state recording control; it does not start or stop the owner recorder.
The owner recorder can be compared against an explicit recording-off launch as
described in step 6.

1. **Open Wave512.** Double-click **Open Wave 512.cmd**. Note the time from launch
   to the first coherent, responsive Workbench view. Keep this first application
   startup distinct from later actor spawning.

2. **Spawn and pilot Needle.** Choose Needle in **Placement model**, choose
   **Place body**, and click clear air in the canvas. Select that instance in
   **Pilot**, click the canvas to release text-field focus, and use **Play /
   Pause [P]** and the normal WASD flight controls. An existing Needle can also
   be selected through Pilot; selecting it does not constitute a new spawn.

3. **Enable real Thruster fire.** Turn on **Thruster fire** and fly for about
   thirty seconds. Observe the actual emitted material, actor visibility and
   response to changes in direction. Repeat briefly with fire off.

4. **Exercise both cameras.** Select **Follow selected**, then **Free camera**.
   Pan with the middle mouse button, zoom with the wheel or the plus/minus
   buttons, and resize the window. Watch the actor and material together during
   camera changes.

5. **Repeat spawn and respawn.** Place one additional actor in clear air, select
   it and use **Reset selected [R]** several times. Remove the extra actor before
   repeating, so the comparison does not silently become an actor-capacity
   stress test. Repeat near existing material and near active Water or Fire.

6. **Compare initial and warmed behavior.** Repeat the same operation several
   times in one session, then close normally and reopen the same launcher for a
   fresh process. Note separately the click response, appearance, first accepted
   movement and any slowdown after the actor becomes visible. To compare owner
   recording off, run `"Open Wave 512.cmd" --recording off` from a Command Prompt
   in the extracted folder. A normal double-click enables owner recording again.
   F10 is not the owner-recording switch.

7. **Edit while playing.** Leave Play running, select **Paint**, and add small
   patches beside the actors. Use right-click to erase. Wait for each ordinary
   edit to settle. A refused edit underneath an occupied actor is different from
   an accepted edit that appears late; retain the displayed reason.

8. **Pick and manipulate actual visible actors.** Use **Select body** on moving
   or rotating actors, including visible members in Water and near a solid
   boundary. Try **Grab physical part**, drag and release. Pause for
   **Place / rotate (paused)**. Confirm that selection follows the geometry that
   was displayed; fully opaque material may legitimately block a pick.

9. **Open the larger authored reference.** Save any work you want to keep, close
   normally, then use **Open Mixed 2048.cmd**. Repeat a short Needle flight and
   the same spawn/reset operation. Keep its observations separate from Wave512.

10. **Exercise Water and Fire contact.** Fly across Water boundaries and beside
    walls with Thruster fire on, then off. Include an actor resting against a
    solid surface under Water. Watch for a disappearing member, a repeated
    moving pose, delayed emitted material or a sudden catch-up movement.

11. **Run a five-minute ordinary session.** Combine piloting, camera motion,
    material edits, one additional spawn, Pause/Play and a manual **Step [.]**.
    Record the approximate time and operation when a hitch occurs. If a useful
    incident occurs, close and collect promptly before continuing another
    session, so its bounded trace is easy to identify.

12. **Exercise prepared-area restoration.** Open **Open Persistent Areas.cmd**.
    Visit A, B and C, paint a recognizable small marker, and return to the same
    areas several times. In **RAM cache…**, inspect **Keep admitted native Worlds
    in RAM**, choose a destination and use **Prepare destination**, then travel
    there after preparation completes. Observe the first restored view and the
    saved marker. Use **Save all areas** and wait for completion. This accepted
    profile is actor-free and uses Current Water; it does not carry the Needle
    or layered Strata from the ordinary Workbench.

13. **Exercise Strata in ordinary Workbench.** Leave the persistent profile with
    **Save & Menu**, close normally, and open **Open Workbench.cmd**. Open
    **Strata Theatre…**. Save current work before loading a supplied example.
    Enable **Layered presentation**, compare **Stack** and **Flat**, select
    **Play** and **Rear architecture** as edit targets, and make a small brush
    edit. Pan/zoom and try the Atmosphere and Optics controls. Check the edit
    target indicator and that Play actors remain coherent. The persistent
    profile deliberately refuses Strata entry.

14. **Save an authored construction.** Finish any active brush or placement
    gesture, enter a unique scene name, and use **Save start [Ctrl+S]**. This saves
    the authored start; it does not promise a snapshot of every subsequently
    evolved simulation cell. Record the scene name and visible construction.

15. **Reopen in a fresh process.** Close normally, reopen **Open Workbench.cmd**
    from the same extracted directory, enter that exact scene name and use
    **Load start**. Check authored material, actor starts, layered content where
    present, camera responsiveness and the first Play transition. The launchers
    share a stable package-local user-data profile.

16. **Collect the evidence.** Close the application normally for the final writer
    flush, then double-click **Collect Results.cmd**. Keep the resulting
    `PUBPRES-results-*.zip`, the application identity in **READ-ME.md**, and a
    short note naming the scene, actor, operation, Fire state, camera and time of
    each incident. The collector exports bounded owner segments and launch logs;
    it never uploads them. It deliberately excludes authored starts and private
    Art conversations. Share a specific saved construction separately when it is
    needed to reproduce a defect.
