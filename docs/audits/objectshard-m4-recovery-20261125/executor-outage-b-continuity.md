## Scheduling and cost interpretation

The reviewed Main/worker/bridge/profile files are unchanged between measured
422 and frozen5f. A genuine Rapier segment must receive its native pose ACK
before the next segment advances; complete intervals must release the exact
due native tick before a new lease is admitted. Main's receipt continuation
runs from its process callback, so slow callback delivery can also reduce
semantic progression. The existing bounded 100-microsecond pending wait
does not waive any barrier.

The Windows Tower headless 180-tick window took 5.986 seconds, with a
4.278-second Main pump that includes waits, a 0.590-second worker snapshot
stage, 0.674 seconds of native occupancy including relocation and 0.073
seconds in the actual Rapier bridge stage. Stress took 6.971 seconds, with
respective stages 5.451, 1.175, 1.638 and 0.095 seconds. These costs overlap
and **must not be summed**. Graphical Tower took 52.401 seconds and Stress
86.706 seconds for the same three seconds of complete physical simulation.

Each of these windows completed 180 native ticks and 180 physical intervals.
721 actual segments were stepped; the last belonged to a new in-flight
interval at the measurement boundary. The 720 acknowledged segments cover
the 180 completed one-body intervals. The later explicit Pause completed
that separate boundary. A missing acknowledgement is never reported as a
completed interval. Full boundary fields and eight-body acknowledgement
counts are preserved in the structured record.

The reported upload stage includes image/patch processing, texture update,
binding and possible engine synchronization. It is not an isolated GPU timer.
Its bounded recent samples can include setup. Physical monitor FPS,
input-to-monitor latency and per-operation allocation costs were not measured.
Fixed overview/zoom profiles are not a continuous camera-pan latency test.
