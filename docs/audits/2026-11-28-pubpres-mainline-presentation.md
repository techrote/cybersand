## Selected architecture and bounded retained presentation

The production changes preserve Stock Safe, Full two-slot publication,
Water-compatible composition, all-worker native completion, the current native
and Rapier owners, and accepted-frame actor picking. No alternative publication
or renderer treatment was made the default.

The retained-endpoint repair addresses a specific gap: a newer material image
can become available before the current native actor response. The old material
certificate then becomes stale even though the previously submitted physical
endpoint may remain admissible. `_revalidated_submitted_water_hold` in
`godot/scripts/main.gd` rechecks that already submitted endpoint against the
actual current and active previous images. It does not select a new pose or
manufacture a new native/physical completion.

The helper retains all of these fences:

- Exact bridge, session, epoch, member identity, generation and body RID.
- Same native World generation, unchanged physical geometry and the exact
  endpoint already present in the submitted frame.
- The original physical step, native tick/sample, native completion time and
  physical completion time. A separate material-revalidation field describes
  the newer visible image identity.
- The resolver's existing shared scan/time allowance and nonrenewable 100 ms
  hold clock. Rechecking an endpoint cannot restart the clock.
- Refusal for unavailable previous history, changed ownership or geometry,
  newly blocking material, exhausted allowance, prior withholding or contact
  clipping. No weakening of the contact policy was adopted.

Specialists A and C independently reviewed the implementation and its refusal
cases. The existing broad Water fixture gained observation of revalidated held
proofs and original clock/pose continuity; its actor population, world, movement,
history-turnover stress, timing allowances and completion thresholds were
preserved.

The separate mounted witness
`godot/tests/test_workbench_retained_water_hold_native.gd` uses ordinary authored
installation and real manual Steps. Exactly one resolver call cannot obtain its
newest native proof. The first post-draw observation must retain the original
endpoint, original native fields and original physical step. A second probe
explicitly supplies an expired original hold clock and must refuse it. Ordinary
mouse input selects the accepted Barrel pose. Only after the first real draw
does the observer briefly freeze processing for hidden/restored pixel controls.
The ordinary runtime then resumes.

This is a controlled missing-response witness. It does not establish the
scheduler cause of the historical omission, general visibility through opaque
material, or physical monitor presentation.

## Windows Water failure: actual Select quantization defect

Specialist B independently downloaded the original Windows Water artifact,
verified its **17,765,281-byte** ZIP and SHA-256, and inspected the raw receipt,
log and framebuffer records before any retry. Import, the two-slot pure Water
case and the three-slot graphical Water case passed. The native graphical case
returned exit 1 after **633.172 seconds**, with **183 checks and two failures**:

1. `submerged_framebuffer ordinary picking uses the presented submerged actor`
2. `initialized, completed, rewet, restored and multipart limb framebuffer controls all execute`

The second failure is consequential: the fixture only invokes its later
`moving_multipart()` stage if preceding failures are empty. Twelve PNGs were
therefore produced for the first four controls; the multipart control was not
executed. This is not a separately diagnosed multipart rendering defect.

The first failure used an actual completed Scooper pose at physical step 132:

| Quantity | Observed value |
|---|---:|
| Accepted position | `(349.966766357422, 492.289581298828)` |
| Accepted angle | `-8.25898553102888e-7` radians |
| First collider center | `(0, 1.71875)` |
| First collider size | `(33, 4)` |
| Collider's local top | `-0.28125` |
| Integer-truncated click | `(349, 492)` |
| Truncated click in the accepted local geometry | approximately `(-0.966766, -0.289581)` |

The truncated point lies just outside every unpadded collider. The accepted
presentation was contact-clipped against basin material, where the existing
picker correctly refuses the usual padded aid unless the point is inside the
actual unpadded part. The continuous pointer at the accepted origin is inside
the real collider.

This was checked against the actual production `CyberPhysicalActorRig` with the
catalogue Scooper definition and a real Rapier body. Exact-pose unpadded picking
returned the chassis; the same call at the truncated point returned empty; a
padded call hit, confirming why the clipped member's deliberate unpadded check
matters. The final raw production-geometry replay log has SHA-256
`368af62366ffaaf6bc9b0bc0a704ee1bb2fe6d901a2e3e099041a5b3649b9612`.

The actor's actual framebuffer contribution remained present: the failed
control's maximum shown/hidden difference was **0.501960784196854**, and its
restored error was **0**. Its native proof was a
`current_completed_native_dependency`, with contact coverage reused only after
the existing identical-material checks. The failure therefore does not justify
loosening native authority, material history, contact clipping or hit padding.

The defect also exists in the ordinary Select input route: it converted the
accepted mouse position into a material cell before calling `_pick`. The narrow
repair changes `_pick` to accept `Vector2` and routes Select through
`world_position_from_local_point(event.position, true)`. It retains the existing
content-bound check, accepted frame/camera, World/session/epoch/member fences,
reverse draw-order hit testing, exact material clip and unpadded contact check.
Painting and placement retain their existing material-cell behavior. Grab
already used continuous accepted-frame positions.

The broad Water fixture now sends an ordinary `InputEventMouseButton` at the
accepted pose, records the continuous point, material cell and owner/frame
identity, and keeps its entire original actor population and history stress.
The new separate `test_workbench_continuous_actor_pick.gd` mounts the exact
failed pose through normal authored setup and actual native material. It checks
continuous-inside versus truncated-outside geometry, real Select input, opaque
material refusal, foreign-owner refusal, restored original-owner selection and
unchanged physical completion count. Its strict focused reader requires all
four ordered mouse outcomes, owner identities, exact source/native/Rapier/engine
hashes and the actual framebuffer hash.

Specialist C independently approved the production change, its witness and the
strict focused reader. Godot parsing and Python compilation passed. A local
mounted attempt ended SIGKILL before startup assertions; it is not counted as
red, green or gameplay acceptance. The new resulting-source Windows focused

## Retained adverse observations and limits

The original failed Windows broad Water receipt records **three omitted body
frames at one actual draw after manual Step 133**: Needle slot 0, Barrel slot 1
and Scooper slot 3. The current response was refused for age; these material
contacts did not have an admissible retained endpoint under the current clipped
contact policy. The reasons and raw native response are retained in
`omitted_observations`, `omitted_by_stage_and_slot` and `omission_reasons`.

The new full-Water endpoint helper deliberately refuses prior contact-clipped
states. Its passing 45-check witness must not be cited as proof that all three
historical contact omissions disappeared. Inspect the resulting-source
selected-owner broad arm separately. If the same condition remains, report its
exact scope rather than weakening the native proof, clock or contact clearance
to force an omission count of zero.

Other unsuccessful observations are retained:

- An earlier paused material-edit-only probe completed four native material
  changes, but its valid Workbench display join never appeared before the
  probe deadline. No first retained draw was observed. The later controlled
  witness uses the original broad fixture's ordinary manual-Step publication;
  the paused-edit observation is not silently reclassified as a success.
- Initial local graphical attempts ended SIGKILL before assertions. An exact
  integrated `c8a41d5a8210d9e36ea0a68089bc0c80200e6b64` staged import also ended
  SIGKILL after 144.53 seconds. Neither establishes a runtime root cause.
- A direct local continuation printed successful assertions for several unit
  cases, but the original process owner returned 125 for suspected surviving
  descendants. Those arms remain invalid. A separate tiny process-owner
  diagnostic later exited cleanly; that does not retroactively validate the
  earlier arms.
- The exact-position Select mounted replay also ended SIGKILL before startup
  assertions. Its successful parser and body-only geometry replay have the
  narrower scopes described above.

The two long paused-history stages in the Windows broad run are intentional:
each observes 280 actual paused frames and then performs 2,056 legitimate
unchanged-body publications to turn over the 2,048-entry bounded history. Their
roughly 288-second and 283-second elapsed intervals are retained. No shorter
substitute was used to pass that registered stress.
