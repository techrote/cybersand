# Collaborative architectural construction owner walkthrough

**Draft / HOLD.** Architecture now offers a searchable structural kit, authored
connection metadata, exact native snap proposals, bounded procedural detail jobs
and a finite task overview. These controls use the existing native World and
ordinary Workbench history. Opening the panel does not start inference or apply
construction. The default intent planner is explicitly deterministic and offline.

This guide describes the executable controls. The mission's final decision
packet supplies the exact qualified source, runtime, test results and evaluator
archive identities. A development run with a reduced native active-core capacity
is not the default-capacity Windows qualification. Hosted graphical qualification
and recorded actor trials also remain separate from physical owner acceptance.

## Open a World and distinguish the three views

Launch the complete evaluator through **Open Workbench.cmd**. Keep its Godot,
native extension, Rapier and project files together. In Shared Workbench, pause
the World and open **Architecture…**.

### Open an already constructed flagship

The supplied starts are ordinary authored documents. **Load start** reads named
documents from the Workbench user folder; it is not a file browser and does not
search the evaluator's evidence directory automatically.

After the first launch, close the application. On Windows, open this folder in
Explorer (create its final `workbench` directory if necessary):

```text
%APPDATA%\Godot\app_userdata\Cyber Sand Reference Sandbox\workbench
```

Copy one source file from the evaluator's
`architecture-evidence\collaborative\flagships` folder into that user folder,
using the destination name below. Keep the source file unchanged. If a
destination already contains your own work, use another valid name instead of
overwriting it.

| Supplied source file | Destination filename | Name to enter beside Load start |
| --- | --- | --- |
| `orbital-fabrication-workbench-start.json` | `setup-m67-orbital-fabrication.json` | `m67-orbital-fabrication` |
| `terraced-arcology-workbench-start.json` | `setup-m67-terraced-arcology.json` | `m67-terraced-arcology` |
| `monumental-viaduct-workbench-start.json` | `setup-m67-monumental-viaduct.json` | `m67-monumental-viaduct` |
| `biomechanical-vault-workbench-start.json` | `setup-m67-biomechanical-vault.json` | `m67-biomechanical-vault` |

Reopen **Open Workbench.cmd**, enter that name and choose **Load start**. Wait
for native loading to finish. This restores the authored geometry paused; it
does not replay a historical Architecture approval or a running simulation.
These flagship starts contain no actor. Add an accepted actor through ordinary
Workbench controls when you want to try movement, or edit the structure first.
The separate recorded gameplay starts retain an external-policy controller and
need an explicit owner control choice before manual play.

The Construction tab separates three kinds of evidence:

| View | What it shows | What it establishes |
| --- | --- | --- |
| Inspected source | A copied material plane from the actual native World | The material identities observed at that inspection; the label identifies staleness |
| Zero-write projection | The exact bounded operation result compiled over that source | Proposed geometry, permissions, footprints and budgets; no native mutation or physics simulation |
| Native result | Verified material readback retained when execution retired | What the native operation actually completed, partially completed or stopped; later World edits may differ |

Use **Fit** to frame the complete extent, **1:1** to inspect one cell per view
pixel, the wheel to zoom and right or middle drag to pan. A fresh source or
projection fits its bounds. Ordinary state refresh preserves owner navigation.
The retained native result is historical evidence, not a continuously refreshed
live World camera.

## Request options through the existing Art provider

The coherent mergedown candidate adds this route. Earlier frozen Architecture
and Art evaluators retain their original controls; they are not interchangeable
with a separately qualified combined package.

In **Intent and tasks**, **Inspect region + propose options** continues to use
the offline planner. For provider-backed options, choose **Configure Art…** and
set the existing Art provider, endpoint, model, key and finite token/time limits.
Return to Architecture, describe the intent, choose its family and bounded region,
and select **Prepare Art proposal…**. This performs a native inspection and opens
a review dialog without sending a request.

Review the destination, model, limits and complete request. The request contains
the intent, inspected material summary and source identity, and bounded
architectural references. It includes no prior Art conversation or image. Choose
**Send this proposal request** to authorize one request, or Cancel. Changes to the
World, intent, model, endpoint, credential or host session require a fresh review.
Provider availability, cost, schema support and creative quality remain properties
of the chosen service; a deterministic engineering fixture does not establish them.

A returned valid option still changes no cells. Adopt the option for review,
select a native task, obtain its current preview, and explicitly approve it.
Each following task needs its own preview and approval. Ordinary Undo owns the
actual native edits. Architecture Stop cancels its proposal; ordinary Art Hide
continues to hide the panel without cancelling an active request. Physical,
creative and complete Windows evaluation remain outstanding for this candidate.

## Obtain the forty-part kit

In Modules choose **Add curated templates**. This adds forty distinct part
templates, preserving existing modules with the same identifiers. The inspector
labels these **UNEXECUTED TEMPLATE** because their material geometry comes from
the bounded code-authored recipes. This action performs no native World writes
and does not pretend to harvest a completed construction.

For native evidence from the packaged qualification, use **Import library…** and
choose `architecture-evidence\collaborative\catalogue\curated-library-v2.json`
inside the extracted evaluator. Imported content retains its
exact module hashes and historical provenance. Its current-session observation
flags start false. An exact identity placement and complete native readback can
establish new observation for that content. A palette, mirror, overlap or changed
empty space must not be mistaken for an exact replay of the original manifest.

**Build 8 starter parts** remains available and really constructs the original
eight parts in private native Batch Worlds before harvesting their readbacks.
Existing Batch experiments stay separate. The ordinary **Harvest native region**
and **Harvest selected Batch tile** entries also remain available. Geometry is
observed; architectural meaning is explicitly authored.

Search names and tags or select a structural part filter. Thumbnails are generated
incrementally from bounded material samples. Selecting a part opens its complete
material plane, local anchor, authored connectors and declared region guides.
The summary distinguishes current observation from imported history and source
templates. **Save modules**, **Import module…**, **Export module…** and
**Rename / tag** operate on library documents, not World cells.

## Declare meaningful local semantics

Select a module and choose **Edit module semantics…**. The form exposes anchor,
allowed grid transforms, material roles, connectors, clearances, protected
regions, fixed geometry and variable geometry. Geometry, provenance and original
recipe remain immutable through this editor.

Each connector has an explicit identifier, local coordinates, facing, compatible
tags, role and contact policy. Version 2 line connectors describe their complete
inclusive occupied span. Full contact must cover both opposing spans; overlap
contact has an explicit minimum and finite capacity. These are authored geometric
contracts, not certificates of physical support, machine flow or gameplay.

Use the visible **Add / Replace** action for edited connector or region fields,
then validate the complete draft and explicitly save it. Validation does not
silently commit the pending fields. A stale form cannot overwrite a concurrently
revised module. An explicit v1-to-v2 upgrade can refuse when the old declarations
do not meet the stronger occupied-face rules. Saving changed metadata retires
the prior current-session qualification for the old manifest hash.

Palette choices are named roles and compatible material identities. **Detail
retained** is enabled only when the module declares variable geometry. It is
bounded pre-placement thinning, not an unrestricted damage operation. Fixed
regions and attachment faces remain protected.

## Place a part and make an exact connection

A compact native connection exercise uses **Stepped bearing foundation** and
**Tapered monumental pier** on an Empty 512 × 512 World:

The Modules tab scrolls vertically. Native target and snap-candidate controls
are below the placement and palette controls; scroll down to reach them in a
small window.

1. In Modules set the authorized region to X128, Y128, W256, H256. Select the
   foundation, choose identity transform, one column and one row, and destination
   X200, Y250. Choose **Propose placement**.
2. In Construction choose **Inspect + zero-write preview**. Inspect the source,
   projection, native checks and refusal conditions. Choose **Approve stage**
   and wait for actual **completed** status and its retained native result.
3. Return to Modules and select the pier's `foot` connector. Set the preferred
   destination to X212, Y186. Choose **Inspect native target connectors**, then
   select the completed foundation's `bearing` contact.
4. Choose **Find bounded snap poses**. The identity proposal at X212, Y186 joins
   two opposing 24-cell faces. The candidate lists the actual span and count.
   Searching poses has performed no writes.
5. Choose **Propose selected snapped placement**, inspect its fresh native
   zero-write preview and explicitly approve. Inspect the final native result.

Only contacts retained from completed placements in the current session become
native targets. Importing a connector declaration does not create a target.
Target inspection rechecks the contact material cells and content identity; it
does not certify the whole part or dynamic stability. The final stage compiler
checks current source, protection, clearances, connector compatibility, capacity
and already reserved contact faces again. Changes to the source or selected
controls require a new proposal and preview.

Ordinary placement still supports permitted mirrors and quarter turns, finite
rows/columns and compatible palettes. Empty module cells are transparent during
placement; a clearance is a separate constraint. An unsupported overwrite or
out-of-region operation refuses before approval.

## Shape bounded detail deliberately

Open **Detail jobs**. The eight executors are mounted ribs, surface trim, anchored
service clutter, framed service panels, mechanical infill, short service routes,
door/window frames and noncritical edge wear. Every executor has code-owned typed
parameters. There is no arbitrary code or model response execution field.

Set a complete inspection region, at most512 ×512 cells, and a contained detail
region, at most128 ×128. Adjust the job's named controls: dimensions, facing,
spacing, density, irregularity, frame thickness, route waypoints or wear amount.
Choose the material, seed and maximum changed-cell budget. A pipe route has two
to eight orthogonal world-cell waypoints; endpoint contact and occupied geometry
are checked against the source.

**Inspect actual source + scopes** retrieves native material bytes and the
current-process part guards. Eligible wear choices require a fully inspected
native instance with unchanged content and exact placed geometry, including its
original Empty cells. Earlier fixed, protected and attachment guards remain in
force even if the library metadata later changes. Import or historical reopen
does not grant live variable-geometry authority. A part without authored variable
geometry cannot be selected as a general erosion target.

Choose **Prepare bounded detail proposal**. The result reports its exact source,
parameters, footprint and finite generated-cell count. Additive components must
touch observed structural material; wear is limited to declared noncritical
Hardwall geometry and its local topology rules. A no-fit or refusal remains
visible. **Review generated native stage** transfers the source-pinned proposal
to Construction. The ordinary fresh preview and explicit approval still follow.
Changing the controls or source invalidates the prepared proposal. **Discard
detail proposal** and the global **Stop / cancel** remain available.

## Discuss intent and review the task hierarchy

In **Intent and tasks**, describe the structure, useful open space, connections
and character. Set a finite region and seed. Choose a family when the request is
ambiguous. **Inspect region + propose options** first observes the actual native
source, then returns up to three named deterministic options or a clarification.
It does not invoke the independently developed Art provider.

Choose one option and **Adopt selected option for review**. The task tree shows
groups, executable leaves, dependencies, executor names and state. Only a
host-compiled budget is displayed as an actual numeric native cost. Proposed,
reviewed and queued work are distinct from completed native work. Select a leaf
and choose **Review selected native task** to reach Construction.

A delegated task becomes available only after its required predecessors have
verified native completion. In Construction choose **Prepare local job**. The
host inspects that task's current native region and runs its bounded procedural
worker. A prepared job is a source-bound proposal: it has queued no native work.
Choose **Inspect + zero-write preview**, inspect the exact footprint and host
budget, then choose **Approve stage**. Changed source, revised controls, Stop,
or a replaced campaign require fresh preparation and approval.

Edit ordinary intent and region fields, then choose **Revise stage**. The optional
advanced typed editor is paginated; it retains the complete document without
shaping a giant JSON value on every update. Revision clears approval. **Skip
stage** does not satisfy its dependencies. **Stop / cancel** retires a proposal
or stops admitted native work at its acknowledgement boundary, retaining any
actual partial prefix and receipts. It never relabels queued operations as built.

**Save decision history…** and **Open decision history…** retain and reopen the
discussion and task decisions. Reopened history is explicitly historical and
cannot resume queued writes automatically. The separate Art successor remains
an integration gate; offline proposals establish no language-model quality.
The task overview also shows the number of retained prior campaign histories.
Starting an explicit recovery plan preserves bounded prior decisions and exact
partial receipts; it does not promote those historical decisions into current
World authority or resume abandoned work.

## Build a large flagship through bounded stages

Construction has a separate four-entry flagship picker alongside the nine
original examples:

| Flagship | Required World extent |
| --- | --- |
| Orbital fabrication hall | 1024 ×1024 |
| Terraced service arcology | 1024 ×1024 |
| Monumental transfer viaduct | 1536 ×768 |
| Biomechanical excavated vault | 1024 ×768 |

Save any existing World first. In ordinary Workbench open **Details**, set **New
width** and **height**, then choose **New blank**. Load the curated template kit
or its matching native library. In Architecture choose the flagship and **Load
flagship tasks**. A smaller existing World is refused with its required size;
the panel never silently creates or erases a World.

The task hierarchy partitions the construction into bounded native regions.
Structure, services, curated parts, context detail and boundary transitions have
explicit dependencies. Review and approve one finite stage at a time. These are
original true side elevations. They use actual material geometry and modules,
not generated concept illustrations. Preserved geometric voids do not alone
prove that every room or level is accessible to an actor.

## Save the authored start and perform physical owner review

**Save session…** preserves the plan and native execution history; it does not
save the World. Ordinary **Save start [Ctrl+S]** preserves the authored native
construction and actor spawn/control choices. **Load start** reopens that
authored start, paused, with new live authority and neutral command leases. It
does not restore a prior landed actor pose or running trajectory. Save modules
separately when the plan depends on their exact content hashes.

For physical review, load the supplied authored start or build the chosen
flagship. Use **Configuration… → Actors → Inspect** to select the actor,
choose **Controllers → Pilot inspected**, and use the controls shown for that accepted model. A saved
external-policy actor will not move merely because Play begins. Choose **Play /
Pause [P]**, inspect movement through the intended route and landing contacts,
then pause before painting. Verify ordinary paint, Undo and Redo, save, close the
process and Load the start again.

The automated witness records selected actual Midge commands, native and Rapier
ticks, trajectory samples, corridor excursions, waypoint visits and landing
contacts. It uses the accepted controller without pose or physics overrides.
Fresh-process checks compare the native route material crop, original spawn and
neutral leases, reject an old issued command and observe new movement. A failed,
stalled, interrupted or development-only trial remains labelled as such. These
specific observations do not establish general traversability, subjective feel,
architectural preference or physical Windows/NVIDIA acceptance.

The owner decision remains Draft/HOLD until the exact delivered evaluator is
reviewed on the intended machine and the remaining Art, model-dependent and
physical acceptance gates are explicitly resolved.

## Delegated workshop and stopped recovery

Use an Empty World of at least 512 × 512 and add the curated templates or import the source-matched curated native library. In Construction, **Load delegated workshop** creates the finite task hierarchy without constructing it. Review each leaf in Tasks, return to Construction for **Inspect + zero-write preview**, and approve only the current projection. The three ready procedural leaves expose **Prepare local job**; preparation reads the actual source and creates a bounded proposal, then requires a fresh preview and approval.

The first access-gallery proposal deliberately intersects a protected passage and should refuse. Select that leaf and choose **Propose clear access gallery** to review the finite repair. The optional screen may be explicitly skipped. To exercise Stop, start the cladding trial and stop it while it is running. Wait for its acknowledged native terminal. **Propose recovery from stopped trial** is available only for that partial stage and requires the stopped region to remain unchanged; the host re-inspects it. The new recovery campaign retains prior history, has separate preview and approval for every stage, and does not erase on selection. If the trial already completed before Stop, this convenience recovery is unavailable; no partial result is invented.

The extracted Windows qualification starts the unchanged **Open Workbench.cmd** in a pristine extraction before any runner import. It records the actual child process, visible window and accepted Workbench route, then closes only that observed process. The source/runtime/payload manifest is checked before launch; later Godot-generated `.import` sidecar rewrites are recorded separately while executable and source bytes remain strict. Subsequent native, UI and full-World actor cases are separate gates. Hosted launcher execution does not establish physical owner acceptance.

## Optional first local-model trial

The current Intent controls remain offline. The [first local-model trial guide](world-steer-first-model-trial.md)
provides five runnable offline preflight commands and a registered three-request
trial for a future qualified owner proposal route. It identifies the exact
missing integration and the evidence a genuine request must retain. This
protocol permits no paid or cloud calls; those require separate owner authority
and an explicit budget. Opening Architecture, importing parts or running the
offline preflight makes no inference request.
