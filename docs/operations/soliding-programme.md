# Scalable reversible soliding programme

## What does issue 12 now own?

**Approved owner direction, implementation Planned:** [issue #12](https://github.com/techrote/cybersand/issues/12)
was reclassified on 2026-09-19 as the foundational reversible representation
programme. Performance in large settled/high-activity worlds and useful macro
physics are co-equal objectives. Phase 0 / PR #23 is retained proof and reusable
material, not the endpoint. This page supersedes the old
[bounded supplement](architecture-programme-prompts/soliding-supplement.md) for
current scope and order, without rewriting its dated evidence or the #14 intake.

**Intake native baseline:** `de332ea` (main including MS-000); successor branch
`codex/issue-12-incremental-foundation`, separate worktree under `C:/kybersand/worktrees/`.
The [Phase 0 audit](../audits/2026-09-19-issue-12-phase0-reuse.md) owns the precise
reuse/adapt/historical/obsolete map. Original `0b96ce2` remains a recoverable
control. No Phase 0 runtime is integrated merely by documenting the lifecycle.
Main's later CI-only update `9c46bf4` is integrated in the successor branch; it
does not change the frozen native control or reinterpret concurrent experiments.

The representation ladder is active cells -> ordinary sleep -> tracked summary
-> measured stationary acceleration -> admitted coherent dynamic aggregate.
Fracture partitions material into coherent moving/stationary children and only
locally loose cellular debris. Rest does not authorize rigid cohesion. Sand and
Stone stationary opportunities remain independent of dynamic admission.

## Which stage may proceed?

| Stage | Entry and work | Exit required before dependent work |
|---|---|---|
| 1. Reconciliation | Audit all PR #23 changes against pinned current main, retain historical evidence and blockers | Compatible reusable primitives, or explicit retained Phase 0 control while a successor replaces them |
| 2. Lifecycle | Reviewed owners, stable nonwrapping IDs, eligibility tiers, fenced transactions, split/merge and failure invariants | Reviewed state table and passing focused transition tests |
| 3. Discovery | Dirty/activity-driven bounded queues and incremental summaries; preserve material semantics | Large-world coverage including seams/components, complete publication, measured amortized cost; no intuition-based size threshold |
| 4. Stationary bake-off | Compare Current sleep, summary/skip, derived proxy and justified compact/boundary representations | Reproducible saving and break-even curves, or explicit evidence-backed rejection of that tier |
| 5. Eligibility | Use material/state authority, preserve support loss/avalanche and wake paths | Useful Sand/Stone stationary behavior without invented rigidity |
| 6. Production dynamics | Admitted coherence plus registry/queue/shape/body/destination capacity and worker/main-thread protocol | Multiple translating/rotating aggregates, exact payload ownership, declared mass/inertia/units, real desktop/Web evidence |
| 7. Geometry/fracture | Measured shape ladder and bounded partition/capacity rules | Coherent children inherit useful parent motion; only loose material reactivates; bounded local rebuilding |
| 8. Persistence | Versioned payload/identity/representation schema and safe pending-state handling | Truthful restore/refusal with source/config identities; no implied exact replay |
| 9. Campaign | Source-matched representation arms and representative worlds | Retained wins/losses, break-even, conservation, behavior and all applicable platform evidence |

Stages are not collapsed to maximize apparent progress. A standalone transition
model tests a contract; it is not a production worker/Rapier ownership kernel.
The first discovery increment may publish complete block summaries while leaving
cross-block connected-region discovery open. Such an increment cannot satisfy
Stage 3 or admit acceleration on its own.

## Performance and physics evidence

The [measurement contract](soliding-measurement.md) starts with ordinary Current
sleep. Bookkeeping that adds cost to sleeping cells is a negative optimization
result. Retain startup, quiet, localized activity and churn separately; include
epoch-wrap work, cold/setup cost and memory. Thresholds follow measured area,
quiet-duration, boundary-activity and churn curves, not a desired percentage.

Macro-dynamics remain first-class: native storage owns exact material/state/
temperature; main-thread Rapier owns transform, velocity, inertia and contacts
only during admitted dynamics. Near-rest zero/known initial velocity does not
invent prior cellular momentum. Falling slabs, off-centre impact/torque and
rotation must lead to coherent child bodies with inherited motion, rather than
a global motionless pixel cloud. The [lifecycle](../architecture/soliding-lifecycle.md)
owns the transition and motion-inheritance requirements. Runtime fixture work
waits for trustworthy integrated ownership; a preregistration is not a pass.

## Completion and handoff

Issue #12 stays open until all programme gates have passing evidence or explicit
evidence-backed no-go/defer dispositions. Opening or merging a successor PR does
not close it. Preserve failed runs, capacity refusals, ambiguity and historical
Linux/provenance blockers. Do not weaken GLIBC <=2.34 or rewrite artifact hashes.
Each checkpoint updates canonical contracts, retrieval routes, scoped evidence
and exact recovery identities, with downstream entry conditions stated.

The blocked [macro-dynamics/fracture fixture preregistration](soliding-macro-fracture-fixture.md)
retains falling, off-centre impulse, free rotation and two/three coherent-child
partitions. It explicitly requires admitted units and real owner integration;
zero loose debris is correct where no loose-material policy has been admitted.

[Successor checkpoint evidence](../audits/2026-09-19-issue-12-foundation.md) records
the foundation; the [Stage-3 exit review](../audits/issue-12-2026-09-19/stage3-exit-review.md)
records the integrated World producer/connectivity admission and every frozen
checklist disposition. Stage 3 is accepted only for the exact reviewed candidate
and remains read-only, cells-owned observation.

The [Stage 3 execution freeze](soliding-stage3-freeze.md) remains the historical and
architectural execution contract. After exact-head CI and merge, Stage 4 is the next
dependency-ready work: preregister the stationary-acceleration bake-off against
Current ordinary sleep. No Stage-3 cost result selects a representation or threshold.
