# Collaborative Art Workbench evaluation

ART-WORKBENCH-COLLABORATIVE-002 extends the ordinary Art workspace with discussion,
reviewable proposals, a session creative brief, bounded World context and explicit
native stage approval. It remains **Draft/HOLD**. Native construction and history
remain owned by CyberSand's existing authoring system.

The predecessor's physical Windows/NVIDIA no-listener report remains an owner
acceptance item. Passing the deterministic demonstrations does not establish a
real model's creativity, model availability or a fix on the owner's hardware.

## Open the portable evaluator

Extract the entire **art-workbench-collaborative-002-windows.zip** to a writable
folder, then double-click **Open Workbench.cmd**. Keep the supplied engine,
libraries, source, dependencies and notices together. Ordinary evaluation needs
no compiler, Git, Python or model server.

Wait for first import and World initialization to finish. Open Art and select the
collaborative page. The existing direct drawing route remains available. The
evaluator creates its own local profile, and opening the application or a panel
sends no model request.

**Ctrl+F12** saves a timing checkpoint. **Open diagnostics.cmd** opens the reports.
The timing report contains phase timings and request states, not prompt text,
keys or response bodies. The complete redacted current-session audit is separate.

The candidate manifest identifies every immutable payload, the package source
and tree, native and Rapier libraries, Godot engine and qualification receipts.
The source/application/package identities are distinct from physical owner
acceptance. Qualification results must be read at their recorded source.

## One conversation, four kinds of request

**Discuss** asks about admitted context or explores an idea. It cannot draw.
**Propose** asks for a finite construction plan, which remains a suggestion until
reviewed. **Develop** refines the current proposal while retaining the applied
brief and its pinned constraints. **Review** asks about observed completed work
and possible improvements. A review response does not automatically approve a
new construction.

Write in the shared prompt and press the mode's Send button. Each collaborative
Send is one explicit request. Preparing a request, waiting for a response,
preparing its result and executing an approved stage have visible states. Stop
is explicit cancellation; ordinary Art X continues to mean Hide.

The Conversation page searches complete admitted message text in small slices.
It shows at most the newest 128 matches and states when the list is bounded.
Selecting a message shows its complete text in 4,096-character parts. The original
**Conversation…** editor remains available for full message editing and its
existing Apply/Cancel semantics. Changing a conversation does not rewrite native
history or the redacted audit.

## Set the creative brief

Use **Focus 256 × 256** for a bounded region centred in the current view. The
Workbench reports its exact bounds after clipping to the World. **Focus viewport**
uses the whole visible native rectangle; **Use selection** uses the PAINT selection.
If a zoomed-out region exceeds the context capacity, zoom in or select a smaller
area before inspection. Use the Creative brief page to record the objective,
style, complexity and variation. Choose available materials, pin constraints and protect native
rectangles. **Apply brief** accepts the draft. **Cancel edits** restores the last
applied brief. Unapplied edits block Send so there is no ambiguity about which
constraints are being sent.

Useful pins are concrete: "Keep the lower passage open", "Preserve the existing
reactor chamber", or "Use only the selected concrete and glass palette". Explicit
protected regions are separate from advisory natural-language preferences.
Where the compiler supports a constraint, it validates it before native
admission.

Destructive permission is off initially. Enabling it does not create a new
material overwrite authority: the existing native owner still decides what can
be written, carved or preserved. Unsupported geometry or material changes refuse
with a visible explanation. The current Art native route can replace Empty and
Hard Wall cells; occupied Metal, Stone and other materials remain protected,
even when destructive edits are permitted. Revising a proposal before execution
can change its material choices; replacing already installed protected material
requires its owning ordinary editor. The [native context/proposal contract](../systems/art-native-context-proposals.md)
records the exact capacities and supported authority.

A brief belongs to the current game session. Hiding Art preserves the session;
a new Workbench game session starts a new conversation. No historical World
reference, execution approval or past audit is silently restored.

## Inspect what will be sent

The Context page separates native material observations, approved knowledge,
session decisions and optional rendered images. **Inspect next context** captures
the bounded information and describes included data, omissions, source identity
and provenance. It does not call a model.

An image preview shows only the explicitly selected canvas capture. Rendered
appearance is distinct from authoritative native material data. The application
does not capture the full desktop, unrelated files or provider credentials.

Review the displayed context before authorizing it for transmission. The
authorization applies to the next explicit request and is invalidated when the
admitted context changes. A configured local/custom endpoint is not evidence of
image support or model availability. Capabilities describe what the adapter can
send and identify unverified model-specific features.

Retrieved documentation is bounded reference material. It cannot grant
permission to execute commands or override the owner's brief. Omitted knowledge
and unavailable context remain visible instead of being fabricated.

## Preview, approve and revise

The Proposal page presents a concise summary, finite stages, dependencies,
materials, host-computed scope and warnings. Select a stage for its details.
Preview predictions are labelled as predictions. Actual changed-cell counts
appear only in confirmed native receipts.

**Refresh preview** performs no native write. **Approve next stage** authorizes
the current applicable stage. It does not approve every later stage. **Revise**
switches the shared prompt to Develop without sending it automatically. **Skip**
uses the current session's supported finite-stage policy. **Copy** copies the
complete structured proposal for inspection without executing it.

Historical revisions remain reviewable and do not retain execution approval.
A relevant manual edit, World replacement or changed source invalidates stale
work. Inspect or replan before approving again. Ordinary manual drawing remains
available through the shared editor.

Stop keeps a truthful record of the native prefix that was actually
acknowledged. It does not claim that multiple completed native operations formed
one atomic transaction. Undo/Redo continues through the existing native history
authority, with its normal pause and source requirements. A continuation requires
fresh applicable validation and approval.

## Try the offline demonstrations

The offline example selector supplies deterministic typed proposals. It neither
contacts a provider nor pretends to be an LLM. Start with a small repair, then
inspect a façade, an interior with preserved clear passages, a protected-region edit and a staged
composition. Compare the original scene, the proposal, zero-write preview and
actual material result.

The ZIP also contains exact evaluated native results. To open a saved example,
close Workbench, double-click **Install evaluated starts.cmd**, reopen Workbench,
enter a listed name such as **art02-industrial_repair** or
**art02-xeno_vault** in the setup-name field, and click **Load start**.
The installer copies only the nine declared starts into the package's own
profile and preserves existing saved files. The last example contains the
complete constructed atlas and paired direct controls. Its result file
identifies the focus region. No provider is needed.

The examples folder contains original before/after native observations,
displayed Workbench screenshots, editable Setup-v2 starts and acknowledged
native receipts. Native diagnostic images and actual framebuffers have
different explicit filenames. The paired direct controls use matched fixture
geometry; identical geometry is not evidence that retrieval improved a model.

Use the bundled creative briefs to vary intent: preserve a passage, substitute
a material, reduce excessive detail, increase irregularity, or resolve
contradictory instructions. Refused cases are useful evidence. A refusal should
explain which bound or constraint prevented execution and should leave the World
unchanged.

The deterministic cohort demonstrates context, validation, lifecycle, preview,
native construction and recovery behavior. It does not prove that retrieval
improves a real model's creative decisions. Architectural part placement through
a separate programme requires its source-pinned owner handoff and separately
qualified integration; a native primitive example is not a substitute claim.

## Configure a real provider explicitly

Return to the existing provider controls to choose an endpoint and enter the
actual configured model identifier. The supported OpenAI, NVIDIA and LM Studio
presets remain conveniences; custom identifiers and endpoints remain editable.
A preset grants no entitlement and is not a model-availability check. Keys remain
in process memory and are not saved in provider profiles or copied to context.

A short owner-operated local protocol is:

1. Start an already installed local model in LM Studio, enable its API server,
   and enter the exact served identifier. Keep image input off initially.
2. Inspect a small native region and use Discuss to ask which material structures
   are actually visible in the admitted context. Verify that no native cell
   changes.
3. Ask Propose for one bounded improvement with a protected passage. Check the
   host preview, approve one stage, and compare confirmed native readback.
4. Ask Develop for a revision, then manually alter a relevant region before
   approval. Verify stale work refuses. Reinspect and submit a fresh request.
5. Use Review after a completed stage. Compare the actual result and the model's
   explanation. Record unsupported claims as failures.

This procedure is explicit, finite and owner-operated. It does not enable paid
inference, download a model or automatically retry failed requests. For a complete
24-brief matched evaluation, retained refusals, true future held-out procedure,
context ablations and qualitative scoring, use the [independent native review and
owner-model protocol](../audits/2026-11-25-art-workbench-collaborative-002/NATIVE-INDEPENDENT-REVIEW.md).

## Retain the original responsiveness acceptance

Completely stop LM Studio and confirm that no listener is running at the selected
local endpoint. Send, then immediately click Art's ordinary X/Hide. Repeat with
Art visible, with Stop before X, and with Hide/reopen. Capture Ctrl+F12 diagnostics
after an observed pause. A running server returning HTTP 404 is a different case.

Keep separate observations for refusal, delayed connection, accepted socket with
no response headers, invalid model, malformed and oversized responses, request
preparation, response preparation, Stop, World replacement and process exit.
The source qualification retains these distinctions.

Cold import and World initialization, body transfer, JSON/preparation, durable
audit append, widget layout and native authoring are separate timing boundaries.
The predecessor recorded a hosted startup gap around 49 seconds, a near-cap
successful response around 48 seconds and an 824 ms maximum frame in that case.
Those results belong to their original source and software-rendered hardware;
they do not certify a physical NVIDIA result or a successor improvement.

## Engineering replay and evidence

The existing Art workflow retains its predecessor matrix and adds the fresh
collaborative suite. Run the new deterministic suite with the pinned Godot 4.7:

~~~text
python tools/ci/run_art_collaborative_gates.py --godot PATH --output NEW_OUTPUT
python tools/ci/run_art_collaborative_gates.py --godot PATH --output NEW_DISPLAY_OUTPUT --graphical
~~~

Graphical Linux execution needs a display such as the existing Xvfb fixture;
Windows uses the established hosted ANGLE path. The runner preserves per-case
original logs, source/tree/runtime identities, checks, failures, timeouts and
phase duration. It is a fixture cohort with zero real-model calls.

The successor package wrapper requires fresh source-matched headless and
displayed Windows receipts and the full-qualification source decision. It
reuses the established fresh-source archive, exact runtime, complete immutable
manifest, actual extracted **Open Workbench.cmd** and loaded-module gates.
No application-reuse shortcut qualifies new collaborative source.

The delivery packet must state the exact qualified commit, platform campaigns,
principal artifact and checksum, retained failures and remaining owner checks.
Until those actual results are recorded, this guide describes the evaluation
procedure and must not be read as a completed qualification claim.

Exact predecessor sources, software-rendered hosted hardware scope and recorded
measurements are preserved in the [provider performance evidence](../audits/2026-11-25-art-workbench-collaborative-002/provider-recovery.md).
