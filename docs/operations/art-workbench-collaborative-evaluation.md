# Collaborative Art Workbench evaluation

ART-WORKBENCH-COLLABORATIVE-002 extends the ordinary Art workspace with discussion,
reviewable proposals, a session creative brief, bounded World context and explicit
native stage approval. It remains **Draft/HOLD**. Native construction and history
remain owned by CyberSand's existing authoring system.

The predecessor's physical Windows/NVIDIA no-listener report remains an owner
acceptance item. Passing the deterministic demonstrations does not establish a
real model's creativity, model availability or a fix on the owner's hardware.

## Open the portable evaluator

For the recovered combined application, extract the entire
**art-architecture-integration-windows.zip** to a writable folder, then
double-click **Open Workbench.cmd**. The earlier frozen Art-only package remains
**art-workbench-collaborative-002-windows.zip**; consult its original source and
qualification identity. Keep the supplied engine,
libraries, source, dependencies and notices together. Ordinary evaluation needs
no compiler, Git, Python or model server.

Wait for first import and World initialization to finish. Open Art and select the
collaborative page. Its first opening expands a compact Art window (up to 640×400) to
an 820×620 workspace when the host has room. Larger existing layouts and all later
manual resizing are preserved; the minimum remains 520×320 with shared actions
reachable.
The existing direct drawing route remains available. Pause simulation with **Play / Pause [P]** before native context inspection, preview or stage approval; those operations require the current paused native source.
Conversation messages still use 4096-character parts. Applying a large edited
conversation shows a preparation state while its complete value is redacted and
encoded. The draft remains readable and Cancel stays available; editing resumes
after Cancel or a refusal. A successful complete journal append updates future
context once. Stop, closing the editor, a replaced World, a newer conversation
revision or changed credentials retires an uncommitted preparation. Apply itself
never writes native cells or creates a native Undo entry. The
evaluator creates its own local profile, and opening the application or a panel
sends no model request.

**Ctrl+F12** saves a timing checkpoint. **Open diagnostics.cmd** opens the reports.
The timing report contains phase timings and request states, not prompt text,
keys or response bodies. The complete redacted current-session audit is separate.

The candidate manifest identifies every immutable payload, the package source
and tree, native and Rapier libraries, Godot engine and qualification receipts.
The source/application/package identities are distinct from physical owner
acceptance. Qualification results must be read at their recorded source.

## One conversation, four kinds of request

**Discuss** asks about admitted context or explores an idea. It cannot draw.
**Propose** asks for a finite construction plan, which remains a suggestion until
reviewed. **Develop** refines the current proposal while retaining the applied
brief and its pinned constraints. **Review** asks about observed completed work
and possible improvements. A review response does not automatically approve a
new construction.

Write in the shared prompt and press the mode's Send button. Each collaborative
Send is one explicit request. Preparing a request, waiting for a response,
preparing its result and executing an approved stage have visible states. Stop
is explicit cancellation; ordinary Art X continues to mean Hide.

The direct model route also requires a finite run: set **Turns** above zero or
set **Run s** above zero before Send. Its default is **Turns 1** and **Run s 0**.
Zero in one field requires a positive bound in the other; both zero refuse before
request preparation or HTTP. A spending ceiling alone does not bound the run.
Direct runs may pace or retry requests within their finite controls. Each
collaborative Send remains exactly one request, without automatic model retry.
Stop remains available in both routes.

The Conversation page searches complete admitted message text in small slices.
It shows at most the newest 128 matches and states when the list is bounded.
Selecting a message shows its complete text in 4,096-character parts. The original
**Conversation…** editor remains available for full message editing and its
existing Apply/Cancel semantics. Changing a conversation does not rewrite native
history or the redacted audit.

## Set the creative brief

Use **Focus 256 × 256** for a bounded region centred in the current view. The
Workbench reports its exact bounds after clipping to the World. **Focus viewport**
uses the whole visible native rectangle; **Use selection** uses the PAINT selection.
If a zoomed-out region exceeds the context capacity, zoom in or select a smaller
area before inspection. Use the Creative brief page to record the objective,
style, complexity and variation. Choose available materials, pin constraints and protect native
rectangles. **Apply brief** accepts the draft. **Cancel edits** restores the last
applied brief. Unapplied edits block Send so there is no ambiguity about which
constraints are being sent.

Useful pins are concrete: "Keep the lower passage open", "Preserve the existing
reactor chamber", or "Use only the selected concrete and glass palette". Explicit
protected regions are separate from advisory natural-language preferences.
Where the compiler supports a constraint, it validates it before native
admission.

Destructive permission is off initially. Enabling it does not create a new
material overwrite authority: the existing native owner still decides what can
be written, carved or preserved. Unsupported geometry or material changes refuse
with a visible explanation. The current Art native route can replace Empty (0) and
Hard Wall (58) cells; occupied Metal, Stone and other materials remain protected,
even when destructive edits are permitted. Revising a proposal before execution
can change its material choices; replacing already installed protected material
requires its owning ordinary editor. The [native context/proposal contract](https://github.com/techrote/cybersand/blob/bcc92927ce3894a16d5544923cfbf7b1d0339fda/docs/systems/art-native-context-proposals.md)
records the exact capacities and supported authority. Its optional online appendix
is not needed to operate the evaluator: the principal bounds are a selected native
capture of at most **262,144 cells**, **one to eight finite stages**, at most
**64 expanded primitive operations**, at most **262,144 conservative raster
candidates per stage** and **1,048,576 overall**. These are host limits, not a
model's context window or a promise that every candidate changes a cell. Body
and actor state is not inferred from the material plane. Native modules,
articulated machines and Architecture-specific plans require their separate
owning authority and are not executable through this primitive proposal schema.

A brief belongs to the current game session. Hiding Art preserves the session;
a new Workbench game session starts a new conversation. No historical World
reference, execution approval or past audit is silently restored.

## Inspect what will be sent

The Context page separates native material observations, approved knowledge,
session decisions and optional rendered images. **Inspect next context** captures
the bounded information and describes included data, omissions, source identity
and provenance. It does not call a model.

An image preview shows only the explicitly selected canvas capture. Rendered
appearance is distinct from authoritative native material data. The application
does not capture the full desktop, unrelated files or provider credentials.

Review the displayed context before authorizing it for transmission. The
authorization applies to the next explicit request and is invalidated when the
admitted context changes. A configured local/custom endpoint is not evidence of
image support or model availability. Capabilities describe what the adapter can
send and identify unverified model-specific features.

Retrieved documentation is bounded reference material. It cannot grant
permission to execute commands or override the owner's brief. Omitted knowledge
and unavailable context remain visible instead of being fabricated.

## Preview, approve and revise

The Proposal page presents a concise summary, finite stages, dependencies,
materials, host-computed scope and warnings. Select a stage for its details.
Preview predictions are labelled as predictions. Actual changed-cell counts
appear only in confirmed native receipts.

**Refresh preview** performs no native write. **Approve next stage** authorizes
the current applicable stage. It does not approve every later stage. **Revise**
switches the shared prompt to Develop without sending it automatically. **Skip**
retires the residual proposal and preview. It does not carry later stages
forward or treat a skipped dependency as completed. Continuing the remaining
idea requires fresh planning, validation and approval. Already acknowledged
native work remains in native history. **Copy** copies the complete structured
proposal for inspection without executing it.

Historical revisions remain reviewable and do not retain execution approval.
A relevant manual edit, World replacement or changed source invalidates stale
work. Inspect or replan before approving again. Ordinary manual drawing remains
available through the shared editor.

Stop keeps a truthful record of the native prefix that was actually
acknowledged. It does not claim that multiple completed native operations formed
one atomic transaction. Undo/Redo continues through the existing native history
authority, with its normal pause and source requirements. A continuation requires
fresh applicable validation and approval.

Use the bundled creative briefs to vary intent: preserve a passage, substitute

## Evaluate the combined Architecture route

This recovered integration keeps one World, one Art request owner and
Architecture's existing native construction authority. It remains **Draft/HOLD**.
Opening either panel sends no request, approves no task and writes no native
cells. The ordinary Workbench starts with experimental Goblin and AMBIENT control
off. The combined Windows campaign, when completed, establishes deterministic
engineering qualification; it does not grant physical or genuine-model acceptance.

This frozen candidate retains the accepted `67c1413a` Goblin001 audit writer,
including its known buffered-write acknowledgement defect. The separate narrow
Goblin repair is not part of this Art/Architecture source. Keep optional Goblin
auditing off here; use the separately source-labelled corrected accepted-main
evaluator for Goblin storage acceptance. The Art storage mechanisms and their
own source-bound qualification remain separately identified.

For a short offline evaluation, open **Architecture…**, choose **Intent and
tasks**, describe a small structure and select a bounded region. **Inspect region
+ propose options** uses the deterministic local planner and needs no provider.
Adopt one option for review. Select a native task, obtain its fresh preview, and
choose **Approve stage** only after reviewing its exact footprint and budget.
Each following task needs its own preview and approval. Inspect the completed
native result, use ordinary **Undo**, then **Redo**. A proposed task is not a
completed construction. **Stop / cancel** retires pending work and preserves any
acknowledged native prefix for ordinary history.

For an optional owner-operated provider evaluation, choose **Configure Art…** in
Architecture and configure the existing Art provider, endpoint, model and finite
limits. No provider is installed or started by this package. Return to Architecture
and choose **Prepare Art proposal…**. This observes the native source and opens a
review dialog without making a request. Review the destination, model, limits,
intent, inspected material summary and bounded architectural references. The
request contains no prior Art conversation or image. **Send this proposal request**
authorizes exactly one request; Cancel sends none. Changing the World, intent,
provider credentials or session requires a fresh review.

A returned valid option still changes no cells. Adopt it for review, obtain the
selected task's current native preview, then explicitly approve its stage.
Architecture owns execution and the ordinary history owns Undo. Architecture
Stop cancels its proposal; closing the Art panel continues to mean Hide.
An absent or failed provider should leave the World unchanged and display a
failure. Do not treat a failed response, refusal or timed-out request as approved
work. Paid inference requires a separate explicit owner choice.

To check persistence, save an authored start under a new name through ordinary
Workbench controls, close the complete application, reopen **Open Workbench.cmd**
and load that named start. Verify geometry and authored settings. Art conversation
and creative history remain session-only; reopening a saved World does not resume
pending provider requests or native approvals. A failed storage acknowledgement
must remain a failure, preserving a previous valid destination for retry.

Owner acceptance asks whether context disclosure is clear, approval and Stop feel
responsive, ordinary Undo/Redo restores the expected geometry, saved work reopens
correctly, and the chosen real model produces useful bounded proposals. Physical
playfeel, creative quality and the predecessor's reported NVIDIA no-listener
behavior require their own owner observations. See the exact package receipt for
which technical checks actually ran; an archive's existence is not qualification.

## Configure a real provider explicitly

Return to the existing provider controls to choose an endpoint and enter the
actual configured model identifier. The supported OpenAI, NVIDIA and LM Studio
presets remain conveniences; custom identifiers and endpoints remain editable.
A preset grants no entitlement and is not a model-availability check. Keys remain
in process memory and are not saved in provider profiles or copied to context.

A short owner-operated local protocol is:

1. Start an already installed local model in LM Studio, enable its API server,
   use the configured numeric **127.0.0.1** endpoint and enter the exact served
   identifier. Keep image input off initially. The hostname **localhost** is
   deliberately classified as unverified; review and authorize its disclosed
   external/custom context when requested. No endpoint is probed merely by
   opening the panel.
2. Inspect a small native region and use Discuss to ask which material structures
   are actually visible in the admitted context. Verify that no native cell
   changes.
3. Ask Propose for one bounded improvement with a protected passage. Check the
   host preview, approve one stage, and compare confirmed native readback.
4. Ask Develop for a revision, then manually alter a relevant region before
   approval. Verify stale work refuses. Reinspect and submit a fresh request.
5. Use Review after a completed stage. Compare the actual result and the model's
   explanation. Record unsupported claims as failures.

This procedure is explicit, finite and owner-operated. It does not enable paid
inference, download a model or automatically retry failed requests. For a complete
24-brief evaluation, use the self-contained protocol below. The optional
[independent native review and owner-model protocol](https://github.com/techrote/cybersand/blob/bcc92927ce3894a16d5544923cfbf7b1d0339fda/docs/audits/2026-11-25-art-workbench-collaborative-002/NATIVE-INDEPENDENT-REVIEW.md)
provides source-pinned background when online.

## Run a complete 24-brief owner-model evaluation

The exact prompt texts are already bundled in
`godot/data/art_collaborative_briefs.json`. The offline proposal generator knows
the fixture mappings; do not present those mappings to a real model as its
answers. A fixture pass proves compiler, context, lifecycle and native behavior,
and does not count as a real-model result.

| Briefs | Role | Scope |
|---|---|---|
| B01–B12 | Development | Industrial repair, façade, concourse, arcology revision, courtyard preservation, foundry palette, Stop/continuation, six-stage megaframe, alien vault, unresolved ambiguity, bounded direct alcove and reduced detail |
| H01–H04 | Reserved owner-model round | Relay elevation, lunar intake, cold-storage settlement and cryogenic corridor |
| C01–C04 | Contradictions and unsupported requests | Protected-region conflict, unapproved palette, destructive permission off and a functional elevator |
| R01–R04 | Revision and recovery | Taller unexecuted proposal, source-Metal overwrite refusal, repair of a protected-region conflict and stale manual-change refusal |

Before the first real-model run, save a starting Setup and freeze the 24 prompt
texts, selected region, palette, protected rectangles, destructive setting,
request budget and scoring rubric. Record the actual served model identifier
and build if exposed, provider, source/runtime manifest, hardware and supported
generation settings. Unknown model details or costs stay unknown. Begin with
text and native context; inspect and authorize an image separately.

Start a fresh game session for each comparison arm, then reload the same initial
native geometry and pause the World. This prevents prior conversation, proposal
and accepted-decision memory from contaminating another arm. Keep the same session
within a brief's intentional revision loop. The fresh native source identity may
legitimately differ after a reload. Compare
existing direct painting, a structured single-stage proposal, a context-enriched
proposal and finite staged construction under the same brief and constraints.
Record the approval and correction effort each workflow actually needs. Do not
force an unsupported arm to pass or silently relax a protection.

For each brief, keep the exact prompt and clarifications, disclosed context and
provenance, initial and final native material hashes, complete redacted reply,
compile/preview/refusal, every stage approval and actual receipt, Stop prefix,
manual corrections, request count, known usage, timing and owner rating. The
current-session audit preserves complete admitted redacted records; it is not
automatically restored as a future conversation. A saved Setup is editable
authored geometry, not a whole simulation replay or a restored execution approval.

For a native-context or knowledge ablation, vary only that admitted information.
Keep the prompt, model, supported settings and output contract fixed.
Counterbalance the arm order and repeat stochastic trials where practical.
Keep all refused, malformed and incomplete attempts in the denominator; do not
retry until a preferred answer appears outside the agreed request budget.
Identical fixture proposals or geometry cannot establish a causal retrieval
benefit.

Keep H01–H04 unused until development decisions are frozen. If a held-out prompt
has influenced tuning, relabel it as development and choose a fresh held-out
text. This is a within-study holdout, not proof that a pretrained model never saw
the wording. The deterministic fixture already knows every mapping and provides
no held-out generalization evidence.

Unauthorized or stale writes, changed protected cells, or invented successful
native receipts fail native correctness regardless of appearance. A truthful
refusal of an impossible request is a useful control outcome and remains a
refusal in the completion count. For other outcomes, rate each of these criteria
from 0 to 3 and keep a short reason: structural legibility; coherent composition
and identity; preservation and requested revision; usefulness of alternatives
and explanations; finite feasible scope and recovery.

| Score | Shared anchor |
|---|---|
| 0 | Fails the intent or misleads the owner |
| 1 | Partly useful but needs substantial repair |
| 2 | Useful and coherent, with constraints retained |
| 3 | Deliberate, economical result that materially helps the owner decide |

Static Empty rectangles establish material clearance, not actor traversal or
physical structural stability. Record any supported actor trial separately or
mark it untested. Keep unsuccessful and disputed judgments. Genuine-model
evaluation remains unqualified until the owner actually performs and records it.

## Retain the original responsiveness acceptance

Completely stop LM Studio and confirm that no listener is running at the selected
local endpoint. Send, then immediately click Art's ordinary X/Hide. Repeat with
Art visible, with Stop before X, and with Hide/reopen. Capture Ctrl+F12 diagnostics
after an observed pause. A running server returning HTTP 404 is a different case.

Keep separate observations for refusal, delayed connection, accepted socket with
no response headers, invalid model, malformed and oversized responses, request
preparation, response preparation, Stop, World replacement and process exit.
The source qualification retains these distinctions.

Cold import and World initialization, body transfer, JSON/preparation, durable
audit append, widget layout and native authoring are separate timing boundaries.
The predecessor recorded a hosted startup gap around 49 seconds, a near-cap
successful response around 48 seconds and an 824 ms maximum frame in that case.
Those results belong to their original source and software-rendered hardware;
they do not certify a physical NVIDIA result or a successor improvement.

Use the immutable manifest to identify the evaluator actually being run. For
orientation, the preserved **bcc92927** hosted Windows campaign recorded the
following separate observations; this table is not a timing guarantee for a
later source or for the owner's machine.

| Observed boundary | Preserved bcc hosted Windows value |
|---|---|
| Pristine Workbench ready / maximum adjacent startup gap | 38.498 s / 34.967 s |
| Edited 16,769,024-byte conversation: Apply click return / observed completion | 13.972 ms / 622.689 ms |
| Maximum frame during that displayed Apply case | 214.778 ms |
| Successful 16,773,391-byte response: transport / complete measured case | 11.332 s / 15.332 s |
| Maximum frame during that displayed response case | 465.486 ms |

The Apply timings distinguish returning control to the owner from finishing all
redaction, encoding and durable journal work. Owner-side adoption in that case
recorded 607.413 ms; the test driver observed completion at 622.689 ms after its
next polling frame. These are different observation boundaries. In a separately controlled single
headless pair on the same host, asynchronous preparation reduced click return
620.436→43.440 ms and maximum frame 639.012→73.356 ms, while total completion
became slightly slower, 620.436→644.979 ms. This demonstrates a responsiveness
tradeoff in that pair, not a total-work speedup or a paired Windows result.
Cold startup and remaining large frame gaps are retained limits. The
[original bcc campaign](https://github.com/techrote/cybersand/actions/runs/45546845554)
and [source-pinned independent package review](https://github.com/techrote/cybersand/blob/c888fcf6b0da41d760a50837034328501e766f25/docs/audits/2026-11-25-art-workbench-collaborative-002/provider-independent-evidence/bcc-windows-independent-review.md)
retain the concrete hosted source, runtime and launcher records.

collaborative suite. Run the new deterministic suite with the pinned Godot 4.7:

~~~text
python tools/ci/run_art_collaborative_gates.py --godot PATH --output NEW_OUTPUT
python tools/ci/run_art_collaborative_gates.py --godot PATH --output NEW_DISPLAY_OUTPUT --graphical
~~~

Windows uses the established hosted ANGLE path. The runner preserves per-case
original logs, source/tree/runtime identities, checks, failures, timeouts and
phase duration. It is a fixture cohort with zero real-model calls.

The successor package wrapper requires fresh source-matched headless and
displayed Windows receipts and the full-qualification source decision. It
reuses the established fresh-source archive, exact runtime, complete immutable

principal artifact and checksum, retained failures and remaining owner checks.
