# LCB-FEEL comparison route (#360)

The route extends the existing liquid comparison panel. It adds no simulation
host, native worker or solver. Each rebuild goes through Main's controlled
prepared-liquid transaction on the exclusive desktop simulation owner, followed
by real native `World::tick()` work. The comparison is sequential A/B: one live
World at a time, one immutable family per material. Four Water laws are never
co-run in one World.

## Launch

1. Run the desktop app (`launch-desktop.cmd` on Windows) and choose
   **Liquid comparison** in the launcher. It opens the protected Dam Break,
   paused, with the comparison dialog docked to the right.
2. In the first picker, choose a `#360` scenario (catalogue below).
3. Choose **Matched IN geometry (radius 3)** or **Preferred per family**. Use the
   first for physical comparison; do not compare timings across the two.
4. Under **Water physical family**, press FreeMass, CellularYield, PressureFlow
   or Inertial. For PressureFlow you may also pick an optimisation variant
   (`cached`, `cached_dormant`). Variants are performance arms, not extra families.
5. Keep **Normalize Water to whole cells on rebuild** checked; the receipt shows
   the exact Water added/removed (zero for every catalogue fixture).
6. Press **Load selected comparison**, then **Run / pause**, **Single step**,
   **Fresh reset** as needed. **Capture run** records the run; repeat steps 4–6
   for the next family. **Export A/B table** writes CSV.
7. To compare worker capacity, choose **Native workers: 1 / 4 / Auto** and
   **Apply workers (fresh owner)**. The scene reloads with a new native owner
   built at that capacity and reapplies the accepted scenario, family, geometry
   and normalization. The setting is in memory only; `project.godot` is unchanged.

**Original Current control** still restores the protected definition with the
unchanged default constructor and radius 2.

## Readout semantics

| Line | Meaning |
|---|---|
| Water selected → applied | Pending request versus native applied assignment readback; a refused rebuild keeps the old applied identity |
| Geometry selected → applied | Requested radius versus the World's applied maximum rule radius |
| Setup | Typed construction receipt normalization (preparation), separate from simulation-driven change |
| Workers | Requested setting, configured pool capacity, and **observed task claimants** from the existing at-most-4 Hz owner sampler. Claimants are not utilization or simultaneous execution |
| Native World::tick | Native tick duration of each consumed publication. Owner step and host frame are separate host costs. Windowed or headless values are not GPU FPS |
| Physical | The scenario's declared observations (for example tank/basin Water at fixed ticks) |

Participation sampling is enabled only while this dialog is visible or this
panel's own accepted comparison session is live. Ordinary sessions keep the
default-off sampler.

## Captures

**Capture run** asks the exclusive owner for the existing MicroScenario capture.
It then writes `user://lcb-feel/<utc>-<scenario>-<family>-c<capacity>.json`
(schema `lcb-feel-app-capture-v1`) and appends a row to `user://lcb-feel/ab-table.json`.
The table survives worker reloads. Each capture stores:

- the applied policy, construction receipt and host-observation identity;
- requested workers, configured capacity, and all participation samples taken during the run;
- the native capture: complete-World Water, explicit source/sink ledger, declared
  observations, and native tick p50/p95/p99/max over the first 3,600 ticks;
- per-publication host samples;
- `"subjective": "UNTESTED"`.

A capture is not a restorable runtime snapshot. Its host evidence keeps
`host_eligible_for_full_matched_evidence=false`.

## Versioned scenario catalogue

Source: [`liquid_feel_catalogue.gd`](../../godot/scripts/liquid_feel_catalogue.gd) (`lcb.feel.catalogue.v1`).
Existing LCB fixtures are reused byte-for-byte. The five new capsules are
generated by [`feel_capsules.py`](../../tools/lcb/feel_capsules.py) (`--check` in CI).

| Slot | Scenario id | Primary measurement / boundary |
|---|---|---|
| 1 | `lcb.feel.leak-side.vented.v1`, `lcb.feel.leak-side.sealed.v1` | 2×2 side puncture opens at tick 120. 13,640 full Water cells in a two-cell Wall tank over a wide basin. Internal transfer, no sink |
| 2 | `lcb.feel.drain-bottom.vented.v1`, `lcb.feel.drain-bottom.sealed.v1`, `lcb.feel.tank-closed.control.v1` | 2×2 bottom drain at tick 120. Sealed lids leave a 14-row headspace that only PressureFlow labels as gas |
| 3 | `lcb.dam.water.freemass.depth-96.v1` | Dam surge, front bands, retained reservoir |
| 4 | `lcb.head.narrow-passage.v1`, `lcb.head.vented-two-limb.v1`, `lcb.head.sealed-two-limb.v1` | Constriction and communicating vessels. Equal levels are valid only for the vented pair |
| 5 | `lcb.rest.deep-quiet-pool.v1`, `lcb.rest.remote-disturbance.v1` | Rest and wake; explicit source at tick 300 and sink at tick 900 |
| 6 | `lcb.shallow.stream-steps.v1` | Scheduled whole-cell 4×4 source every 30 ticks to tick 600, then the stop tail. **No directed-momentum inlet exists**; that belongs to #361 |
| 7 | — | **Unavailable in the controlled actor-free route.** Use Exploratory with a supported body MicroScenario; contact/splash analysis belongs to #362 |
| Mixed | `lcb.mixed.water-oil-brine.v1`, `lcb.density.water-brine-lock-exchange.v1` | Per-material families in one World (for example Water PF or Current, Brine IN, Oil CY) |

The capsules are **open-only through tick 1200**. Scheduled events can erase
Wall but cannot place it, so the proposed tick-600 closure is not representable;
reversible openings belong to #361's tools.

## Owner playtest sheet — UNTESTED

Use one fixed view and the same speed for every family. Run each scenario at
matched radius 3 with workers Auto, then repeat any interesting case at 1 and 4.
Rate each family 1–5 (5 best) or write a note.

**Every field is UNTESTED until the owner fills it in.** Automated results
establish correctness and measured cost only. They do not establish which model
looks or feels best.
