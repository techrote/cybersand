## Falsifier preregistration

**Claim challenged:** after `Fence.accept` verifies a packet's `check`, an acknowledged producer contribution is stable until `Fence.advance` reduces the complete worker barrier.

**Test:** at generation 0 / tick 0, accept a packet containing a nested mutable event list `["pressure", 0]`; after acceptance and before `advance`, mutate the *same list* to `["pressure", 1]`. Supply the remaining empty shards so 1/4 logical worker barriers are complete. Independently compute the full reference next state from the *accepted* `("pressure", 0)` event. Repeat with a local `set` changing ROCK to Water after acceptance.

**Required safety property:** either freeze an immutable canonical event snapshot on acceptance and execute that exact snapshot, or atomically reject an altered packet before any authoritative state changes. The complete-barrier condition by itself is insufficient if the acknowledged packet bytes are mutable.

## Independently inspected source mechanism

The exact B2 source's `Packet.make` uses `tuple(events)`, which is **shallow**: mutable inner `list` objects remain shared. `Packet` is a frozen dataclass, but a nested list is not frozen. `Fence.accept` checks SHA-256 once and then stores the packet object in `self.packets`. `Fence.advance` iterates its present `p.events` without rechecking the admitted digest. Its event preflight explicitly accepts both tuples and lists. Therefore a well-typed accepted packet can be altered between admission and reduction without modifying the frozen outer dataclass or its recorded `check`. This is a research model's reference/aliasing hole; the model explicitly disclaims any cryptographic worker authentication.

A separate **minimal local Python shadow replay**, reproducing only the packet/digest/accept/reduce ordering (not running the actual B2 module), exercised the remote-pressure mutation under a complete four-shard barrier:

- Accepted packet SHA-256: `8827301f776d84ef8a4c568673daa2d9c1a401bdc4912a1a2aa22b6b65de0319`.
- SHA-256 of the same aliased packet after mutation: `afe8a3a78cbd549cc20566741ca592ac53ffefdc17728652caf3661e6dda76cc`.
- Shadow barrier returned `COMMITTED` and applied pressure **1**, though the accepted value was **0**.

This is **executed shadow evidence + independent exact-source control-flow inspection**, not a verified execution of the complete B2 published module. The changed digest alone is not a collision or cryptographic break.

## Independent review / minimal correction

**B2:** Treat accepted packet payloads as owned, canonical, bounded **immutable** snapshots, or verify their signed/hashed canonical bytes at the final owner barrier and refuse before any writes. Cover nested list payloads (`set`, `body`, global `pressure`), 1/4-shard order, rollback/generation, and preflight all events before mutation. Do not simply add a hash comparison to a mutable object after some events have been applied.

**B5:** Explicitly add `stable_effect_payload` to the hypotheses of `CompleteOwnerBarrier(generation,tick,worker-set,effects)`. A packet set with complete shard IDs but mutable accepted payload is not yet a certificate of complete owner *effects*. Provenance must be tied to native producer-owned immutable inputs, not to caller-calculated SHA alone.

**B4 performance:** Deep canonicalisation or digest revalidation costs `O(packet_bytes)`, with model-side packet count bounded by 1 or 4 and events bounded to 24 per packet, but no measured cost, RSS, allocation delta or real CyberSand worker participation. Test any eventual production mechanism with a same-host A/B/B/A native campaign only after a separately approved candidate; require per-tick physical hash, quantity, gas/pressure and Rapier contact parity as well as p50/p95/tail and memory. **No such campaign was run or authorised.**
