# PUBPRES recovery qualification

This continuation preserves all frozen source, receipts, readers and the c2
Windows evaluator. It adds a distinct resulting-source qualification route.
No green job selects a renderer, enables a default, merges a PR or certifies a
physical display. Every run retains physical owner **HOLD**.

## Deliberate runs

`.github/workflows/pubpres-recovery.yml` responds only to the principal
continuation branch changing `.github/pubpres-recovery-run.json`. The request
binds the complete committed Git tree except itself, the frozen c90 predecessor,
a concrete purpose, and one prospective phase:

- `stock`: original nineteen correctness cases under the exact official Safe
  engine, followed by the newly registered pure, framebuffer and mounted native
  Water gates. Actual-submission is off because stock has no atomic admission.
- `integration`: the same stock gates, then the separately admitted atomic
  engine's frozen Safe inventory, actual transaction refusals under Safe0,
  Separate0 and Separate4, mounted Water under Separate0/4, font parity against
  stock Safe, ordinary native startup and exact two-slot first GPU reads.

The Linux job is an independent stock qualification in either phase. The atomic
payload is Windows-specific. Each stage records its exact command and original
output. Failed prerequisites record the dependent unexecuted gate. Focused
correctness success is not comparative performance qualification.

The integration request must pin the engine artifact's numeric ID, name,
original build source, run, attempt, archive SHA-256 and independent provenance
SHA-256. The artifact is fetched using read-only Actions access. The payload's
original strict source, compiler, API, PE, file and four-patch composition gates
run before its executable is used. A changed engine input requires a new build.

## Native artifact reuse

`retained_artifacts.json` names the original campaign's independent Linux and
Windows C/D runtime archives. `restore_inputs.py` checks the service identity,
archive digest, CRC and canonical file inventory. Original archives and their
extracted original receipts remain unchanged. The C execution copy receives an
additional `PUBPRES-NATIVE-INPUT-REUSE.json` which binds the new application to
exactly identical complete native and build-policy inputs. The original build
source remains 4bde; it is never renamed as the new application. Any changed or
new native input is refused and requires an independent rebuild.

`retained_runtime.py` rechecks this binding at execution and calls the unchanged
host-platform runtime validator on the original build identity. Prior gameplay
results are never inherited by this input-equivalence join.
