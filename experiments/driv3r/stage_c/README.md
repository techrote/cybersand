# CyberSand DRIV3R — Stage C graphical native pilot

This opt-in pilot continues the source-qualified Stage B cohort after its predeclared GO_TO_BOUNDED_STAGE_C gate. The gate does not demonstrate superiority over strong geometric code.

## Execution, restrictions and scope

- Six frozen new one-choice episodes: two Pipework, two Architecture and two Greebles, all using different real native fixture layouts.
- Existing v2 Art compiler expands each host-defined program into bounded material58 rectangles. Each selection uses the same Workbench permissions, native receipts, Stop, readback and replay as Stage B.
- A maximum of three decisions per episode, 1024 changed cells, and one real Q8 resident model. Poor choices and refusal are retained; frozen target footprints are not used to repair model choices.
- The same official Q8 GGUF and pinned llama.cpp build, Linux Godot 4.7, source-built native extension and pinned Rapier are used. Stage B archive digest and recorded GO are verified before execution.
- Software-rendered Xvfb Godot gl_compatibility provides a genuine root Viewport framebuffer PNG, recorded separately from original material-derived PNG. Capturing a frame must not mutate generation, revision, tick or material hashes.
- Each original episode receives actual native replay. Extreme numeric coordinate inputs must refuse with zero World changes, and headless framebuffer requests must explicitly refuse.
- A dedicated request-file-only GitHub Action runs the heavyweight campaign; normal PR changes do not launch it. Immutable artifact and prerelease identities bind source SHA and Actions run.
- No training, scheduled workers, merges, Ready transition, production-default change, reference-model or Q4 substitution.

## Qualification and interpretation

Six original cases use host-selected three-way profiles: a pipe bend and T-junction; a room doorway and ledge brace; a vent and grille panel. The target footprint is derived independently from each frozen program; actual score is computed from original stored-material readback, not candidate IDs. A successful graphical capture proves that the real display path generated a nonblank PNG, not that the game level has good artistic quality or that Windows GPU output matches.

Entrypoints: experiments/driv3r/stage_c/qualify.py, experiments/driv3r/stage_c/provenance.py, experiments/driv3r/stage_c/cases.json, experiments/driv3r/ci_stage_c.sh and .github/workflows/driv3r-stage-c.yml.

The Stage B decision to test these three families does not authorize further expansion, training or release merge.
