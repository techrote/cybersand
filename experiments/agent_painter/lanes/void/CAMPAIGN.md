## First candidate protocol

The dedicated `campaign-request.json` (once explicitly added) triggers one 16-update, real LoRA run using the **qualified reusable** `agent-painter-train.yml` and pinned VOID/CPU/source/native-corpus contracts. The native-admitted TRAIN rows come from `633920373a3d406a2ede61ce4137c324f76be23b`; the newer model-preflight source remains separately attributed.

The second job downloads the new immutable checkpoint into a fresh GitHub-hosted VM, verifies its inventory and source/adapter/model/compiler/numerical identities, then runs **12 original DEVELOPMENT seed views (six distinct language requests)** on the untuned base and trained adapter. It retains first-pass token IDs, EOS/JSON/compiler rejection, original text and compiled operations, and complete denominators. No correction, retry, substituted teacher, or prompt-dependent fallback is permitted. It does not inspect sealed FINAL, train on DEVELOPMENT, call generated operations native-executed, invent PNGs, or claim visual success.

The model is the original `dotlabs/void.1@9c2be5087772867d45961abd11f6b35110617563`: 259-symbol strict byte tokenizer, explicit non-chat `cybersand-void-task-v1` framing, EOS 258, 2,048-token context, FP32 one-thread math, 168 language LoRA modules. Only a new explicit, separately qualified candidate may alter these contracts.

This **16-step first pilot** is an evidence-generating diagnostic, not expected to establish a useful painter by itself. The subsequent substantial campaign must introduce a versioned, **lane-owned** larger-step wrapper with bounded checkpoint cadence, per-job deadline, public immutable candidate freezes and raw native evaluation. Do not remove the shared 1–16 proof guard to get longer runs; do not retrigger this pilot on an hourly schedule tick. When a useful version is frozen, coordinate matched fresh-from-parent versus continued-from-copy experiments on up to two **separate** hosted Actions VMs (one model training process per VM).

No PR merge, default promotion or production native authorization is implied. For any accepted compiler program, actual native material acknowledgements, original PNG and readback verification remain a separate source-matched acceptance gate.
